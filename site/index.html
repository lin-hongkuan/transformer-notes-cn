Chapter 00 · 导论

序幕：一个思想的诞生

在深入任何公式之前，先搞清楚一件事：Transformer 到底解决了什么问题，以至于全世界都为它疯狂？

你其实早就见过 Transformer

你大概已经用过 Transformer 的后代：GPT、Claude、Gemini、DeepSeek 等语言模型大量采用 Transformer 变体；机器翻译、语音识别、图像生成等系统也会在不同位置用到它。先把边界说清楚：这些产品不一定全由同一种网络构成。例如 Stable Diffusion 的核心去噪网络以 U-Net 为主，但其中用交叉注意力连接文字条件；早期 DALL·E 使用自回归 Transformer；Whisper 则是编码器—解码器 Transformer。Transformer 是一套可复用的计算架构，不是所有 AI 产品的同一个“发动机”。GPT 的全称 Generative Pre-trained Transformer，名字里就写着它。

重要起点是 Google 团队在 2017 年发表的论文 《Attention Is All You Need》。八位作者提出一种完全以注意力为核心的序列转换模型，在机器翻译上展示了高质量和并行训练的优势。“Attention Is All You Need”是论文标题，也是一句聚焦于该架构设计的主张；它不表示整个学习系统只剩一个注意力公式——论文里的 Transformer 还有前馈网络、残差连接、归一化、位置编码和输出层。

语言的难题：顺序、距离与遗忘

在 Transformer 之前，AI 处理语言的主流武器是循环神经网络（RNN）和它的改进版 LSTM。它们的工作方式像一个人逐字阅读：读第一个词，记住；读第二个词，更新记忆；读到第一百个词时……开头说了什么，已经模糊得差不多了。

想象你在读这句话：

类比

「那只小猫追着毛线球跑过了整个客厅、跳上沙发、钻进毯子底下，最后它终于累了。」——当你读到"它"时，你的大脑瞬间就知道"它"是"小猫"，中间隔了十几个字也毫无压力。但对逐字处理的 RNN 来说，这段距离就是记忆力的灾难。

Transformer 的关键改变是：在一个注意力层里，把句子中各位置的表示放在一起计算，让每个位置能直接从其他允许访问的位置收集信息。注意力（Attention）会根据当前内容，为不同位置分配不同权重，再将那些位置的信息汇总。若两个词相隔很远，它们仍可在一层注意力中建立直接联系；这比必须逐步传递状态更容易连接远距离信息。但这不代表模型“永不遗忘”：信息仍可能被训练出的权重忽略，长输入也受上下文长度和计算量约束。注意力提供的是一条直接的信息通路，而不是人脑式的理解保证。

一张时间线看懂它如何统治世界

它的跨界能力来自一个抽象：只要能把输入组织成一串向量，就能尝试用注意力在这些位置之间交换信息。视觉 Transformer（ViT）把图像切成 patch；Whisper 把音频转成声学特征序列并采用编码器—解码器 Transformer；AlphaFold 2 的 Evoformer 也使用注意力运算来处理蛋白质相关表示。这些系统的输入、目标函数和其他组件并不相同，架构思想可迁移，不等于只替换数据就能直接得到另一个领域的模型。

先建立正确边界

“Transformer 很强”是一条经验，不是“Transformer 会自动理解一切”的定理。模型从数据与训练目标中学到统计规律；它能否回答好问题，还取决于数据质量、模型规模、训练方法、推理设置和评测方式。接下来我们学的是它如何计算，以及这些计算为什么有用。

0.1 先看见整台机器：输入、变换、输出

拿一个极小的翻译任务做地图：输入句子 “我 喜欢 猫”，目标句子是 “I like cats”。模型并不是把中文词典逐条查成英文词典。它先把输入切成 token，查表得到向量，加入位置线索；随后层层变换这些向量，让每个位置结合上下文更新自己的表示。输出端把每个位置的表示映射到词表分数，再按任务规则挑出英文 token。

把它拆成四个问题，后面每章都会回答其中一块：

1 · 怎么表示

词元如何变成向量？嵌入表与位置编码分别提供什么信息？

2 · 怎么交流

一个位置如何判断当前应从哪些位置取信息？这是注意力的工作。

3 · 怎么变聪明

注意力、前馈网络和残差等模块怎样堆叠；训练误差又怎样调整参数？

4 · 怎么生成

模型如何把词表分数变成下一个 token，并在推理时逐步生成文本？

一个很有用的区分是：架构是计算步骤，参数是训练出来的数字，能力是模型在任务上的表现。看懂架构图，不等于知道所有权重里存了什么；知道模型参数量，也不能单凭这个数断定回答质量。学 Transformer 时，我们会先追踪信息流，再讨论训练目标和能力边界。

常见问题 FAQ · 先把整张地图读明白

下面的问题围绕本章的总览展开。遇到新术语时，先判断它位于“文本输入—数值表示—层内计算—输出”哪一站，再继续往下读。

Transformer 只适合处理文字吗？

不只处理文字，但输入必须先转成模型可计算的表示。语言模型通常把文本切成 token，再把 token 映射成向量；视觉模型可以把图像切成 patch，音频模型可以把波形变成声学帧或离散音频 token。只要任务能组织成一组带有位置或结构信息的表示，注意力就能在这些表示之间交换信息。

这并不表示同一个模型无需改动就能通吃所有数据。图像 patch、音频帧和文字 token 的含义不同，输入编码方式、训练目标、位置设计和输出头也可能不同。更准确的说法是：Transformer 提供一套可迁移的计算骨架，具体系统仍需为任务设计表示和训练方法。

注意力可以直接连接远处的词，是否就等于模型“记住了”它们？

不等于。在一次注意力计算里，当前位置可以直接读取允许访问的远处位置，不必像 RNN 那样把信息逐步经过每一个中间时间步。这解决的是“信息有没有一条直接通路”的问题。模型是否真的利用了那条通路，还取决于训练得到的投影、打分和后续层；注意力权重也可能把相关位置分得很低。

此外，模型只看得到上下文窗口内的输入，长序列的计算和显存成本也会限制可读范围。因此，“远距离交互更容易”是架构性质，“永远不会遗忘或必然理解指代”则不是保证。

为什么要用 Transformer？RNN 不是也能读句子吗？

RNN 能读，也曾是序列任务的重要架构。它按时间步递推：先算第 1 个位置的隐藏状态，再用它和第 2 个位置算下一状态。于是同一条序列的时间步有先后依赖；在训练期间，即使整句都已知，第 20 步通常仍要等第 19 步的状态算出后才能计算。

Transformer 在一层里用矩阵运算同时处理所有已知位置，并以注意力建立位置之间的联系，因此训练阶段更容易并行利用 GPU。代价是标准全注意力通常要比较大量位置对，分数矩阵随序列长度平方增长；而自回归生成时，下一个 token 仍要等上一个 token 生成。两种架构各有计算特点，Transformer 并没有消灭所有顺序依赖。

“Attention Is All You Need”是不是说 Transformer 只有注意力？

不是。这是 2017 年论文的标题，强调论文提出的序列转换架构不再依赖 RNN 或卷积作为主要的序列建模骨干；它不是逐字的组件清单。标准 Transformer 层还包含逐位置前馈网络、残差连接和归一化，完整模型另有嵌入、位置表示、输出投影及任务相关训练目标。

注意力主要负责让位置读取其他位置的信息，前馈网络则在每个位置上继续变换特征。残差和归一化帮助深层网络训练。读架构图时应把这些职责分别看清，而不要把论文标题误读成“一个注意力公式就完成了全部工作”。

Chapter 01 · 打地基

预备知识：只需要这三块积木

本章专为零基础读者准备。只讲三样东西：向量、矩阵乘法、概率。每一样都配上"为什么要学它"。

1.1 向量：给"意思"一个坐标

向量就是一串有顺序的数字，比如 [0.2, -0.5, 0.8, 0.1]。你可以把它想象成一个多维空间里的箭头——两个数字就是平面上的一支箭，512 个数字就是 512 维空间的一支箭。人脑无法想象 512 维，但没关系，所有直觉在 2 维里建立，数学上完全通用。

类比 · 为什么要学它

电脑不认识"猫"这个字，但它认识数字。Transformer 的第一步就是把每个词变成一个向量——相当于给每个词发了一张"多维坐标身份证"。后面所有计算，都是在这些坐标上做的。

一个容易踩的坑：点积不总等于“相似度”。因为 a · b = ‖a‖‖b‖ cos θ，它同时受方向和长度影响。比如 [10, 0] · [1, 0] = 10，而 [1, 0] · [1, 0] = 1；两对向量方向完全相同，点积却不同。若先把向量都归一化为单位长度，点积才等于余弦相似度 cos θ：同向为 1，垂直为 0，反向为 −1。Transformer 的注意力会学习 Query 和 Key 的投影，再用原始点积打分；训练中向量的尺度也会影响分数，因此下一部分会用 √dₖ 缩放来控制数值大小。

动手感受

把两个方向相同的箭头，一个画成短箭头、另一个画成长箭头。方向相似度一样，但点积会因为长度不同而改变。可以把余弦相似度想成“只比较朝向”，把点积想成“朝向 × 两支箭的长度”。

1.2 矩阵乘法：一次算完所有配对打分

矩阵可以看成按行、按列排好的数字表，也可以看成一组向量。把 3 个 4 维向量各放一行，得到形状为 3×4 的矩阵：3 表示有 3 个对象，4 表示每个对象有 4 个特征。矩阵乘法的规则是：结果第 i 行第 j 列 = 左矩阵第 i 行与右矩阵第 j 列的点积。要做这次点积，两边参与运算的长度必须一样，这就是维度规则中间的 k 必须相等的原因。

关键洞察 · 为什么要学它

一个格子是一次点积；整个结果矩阵就是"两拨向量之间所有两两打分"的总表。若参与运算的是单位向量，分数才可直接读作余弦相似度；注意力里的 Query 和 Key 通常不是单位向量，因此 QKᵀ 更准确地说是模型学出来的相关性分数。它用一次矩阵乘法，算出"每个 Query 对每个 Key"的成对分数。GPU 擅长这类大规模矩阵运算。

顺手记住维度规则：(m×k) × (k×n) = (m×n)——左边有 m 行，右边有 n 列，结果为每种行列配对各算一个点积，所以是 m×n；两侧的 k 是点积的长度，会被“消耗”掉。这条规则能帮你检查后面出现的公式。例如，若一串含 n 个 token 的 Query 和 Key 各有 dₖ 个特征，Q 形状是 n×dₖ，Kᵀ 是 dₖ×n，那么 QKᵀ 必为 n×n：每一格就是“一个 Query 与一个 Key 的打分”。

矩阵乘法不等于逐格相乘

图中的 A×B 是矩阵乘法：取一行与一列做点积。它不同于同形状矩阵“对应格子相乘”（常记作逐元素乘法）。两种运算都会出现，但 QKᵀ 用的是矩阵乘法。

1.3 概率与加权平均：注意力的记账方式

第三个概念更简单：概率分布是一组非负、总和为 1 的数，比如 [0.7, 0.2, 0.1]。它可用来做加权平均：先把每个候选向量乘上相应权重，再逐项相加。由于权重总和为 1，结果会落在这些向量的“加权中心”上。若权重很集中，结果更靠近权重最大的向量；若权重平均分配，结果就综合多方信息。

三块积木如何接起来

一句话里每个 token 先对应一个向量；点积把两个向量压成一个数，提供打分；Softmax 把一组打分变成总和为 1 的权重；加权和再把许多信息向量汇成一个向量。第 4 章会把它们接成一条完整的注意力计算链。

常见问题 FAQ · 数学积木如何不再混淆

本章的向量、点积、矩阵和概率都是注意力的基础语言。下面把“数值表示什么”与“它在网络里做什么”分开说明。

向量里的每个数字，分别代表一种明确的人类属性吗？

通常不能这样逐维解读。向量是若干实数构成的坐标，训练会调整这些坐标，让整个网络更容易完成预测任务；某些方向可能与可辨认的属性相关，但一般没有“第 17 维就是过去时”这种稳定的一对一约定。不同模型、不同层甚至同一模型的不同训练过程，都可能用不同坐标组织相似信息。

因此，向量最可靠的解释通常来自它参与的计算：点积给出一个兼容性分数，矩阵乘法把一批变换一起算完，后续网络再组合特征。可视化投影能帮助建立直觉，却会丢掉高维信息，也不能替代对实际运算的理解。

点积为什么能表示“相似度”？它会不会被向量长度影响？

点积同时考虑方向和长度。对向量 a、b，有 a·b=‖a‖‖b‖cosθ：方向越接近，余弦项通常越大；但只要把其中一个向量的长度放大，点积也会随之增大。因此它不是纯粹、天然且与尺度无关的语义相似度。

在注意力中，Query 和 Key 是从隐藏表示经过可学习投影得到的，模型通过训练学会怎样使用它们的点积打分。常见缩放点积注意力还会把分数除以 √dₖ，控制维度增大时分数尺度过快变大的问题。若先对向量归一化，点积才等于余弦相似度；标准注意力一般并不把 Q、K 自动归一化成单位长度。

QKᵀ 为什么会得到“每个 Query 对每个 Key”的分数表？

假设有 n 个位置，每个 Query 和 Key 都是 dₖ 维，并把每个位置放成一行，那么 Q 的形状是 n×dₖ，Kᵀ 的形状是 dₖ×n。相乘后形状为 n×n：第 i 行、第 j 列就是 qᵢ 与 kⱼ 的点积。

行索引回答“哪个位置正在查询”，列索引回答“它正在比较哪个候选位置”。例如长度为 5 的序列得到 5×5 分数表，每一行再经过 Softmax 和掩码处理，才会变成读取 Value 的权重。这个形状检查法很实用：先写清每个矩阵的行代表什么、列代表什么，再做乘法。

Softmax 为什么要先取指数？大分数时怎样避免数值溢出？

指数把任意实数分数变成正数，再除以总和即可得到非负且和为 1 的权重。若直接把原分数除以总和，负分数会产生负“概率”，总和为零时还会无法计算。Softmax 也具有平移不变性：所有分数同时减去同一个常数，概率分布不变。

实际计算通常选最大分数 m=max(z)，计算 exp(zᵢ−m) 再归一化。这样每个指数的输入都不大于 0，最大指数为 1，避免直接对很大的正数取指数时溢出。训练框架往往把 LogSoftmax 与交叉熵合成稳定实现，因此手写训练代码时通常把原始 logits 交给交叉熵损失，而不是先手动 Softmax 再取对数。

Chapter 02 · 打地基

词嵌入与 Softmax：文字如何变成可计算的数学

电脑只吃数字。本章解决两个问题：怎么给每个词发一张"向量身份证"，以及怎么把任意分数变成概率。

2.1 分词：先把句子切成"积木"

模型读句子之前，要先把它切成基本单位——token（词元）。Token 是模型词表中的符号单位，不一定等于一个汉字、一个英文单词，甚至不一定等于人类语言学里的“词”。许多模型用子词词表：常见片段可以整体收录，罕见词则拆成更小的片段。下面是教学用的示意切分；实际切分取决于具体模型的 tokenizer 和词表：

tokenization 示例"unbelievable"  →  ["un", "believ", "able"]

为什么要切碎？因为词表不能无限大。若每个可能的整词、专名、拼写变体都单独收录，表会非常庞大；子词让常见片段有独立编号，较少见的字符串还能拆开表示。它缓解了“词表大小”和“序列长度”的矛盾，但有代价：不同语言的切分效率不一样；罕见词往往被拆成更多 token；token 边界也不保证对应语义边界。模型先把文本编码为 token ID 整数序列，随后才查嵌入表。ID 是任意标签，就像字典页码；数值相邻不表示两个 token 相似。

词表与切分方式

BPE 是一种从高频相邻片段合并构建词表的方法；SentencePiece 是支持从原始文本训练子词模型的工具框架，可实现 BPE 或 unigram 等算法。它们不是同一层级的术语。真实 tokenizer 还负责空格、标点、特殊 token 等细节，所以同一句文字在不同模型中可能得到不同 ID 序列。

一个最小 BPE 合并演算：字符怎样长成子词

为了看清算法，只造一个微型语料：low 出现 3 次，lower 出现 1 次；暂时忽略大小写、空格标记和 UTF-8 字节。起步时每个词按字符列出。所有相邻对里，l-o 出现 4 次、o-w 出现 4 次、w-e 和 e-r 各 1 次。为打破并列，假定这套玩具算法先选 l-o。将每处相邻的 l 和 o 合并为一个符号 lo 后，再重新数相邻对；此时 lo-w 出现 4 次，于是可再次合并为 low。

真实 BPE 的基本思想与图中相同：从初始符号开始，统计训练语料里的相邻对，按规则选出合并项并记录合并次序，重复直到达到词表规模或合并次数。推理时使用已学好的词表和合并规则切分新文本，不会针对当前句子临时重训。现代 byte-level BPE 通常从字节序列开始，并处理空格边界、字节可见化与规范化；实际实现的词频统计、边界符和同频处理更完整，所以这张图只展示核心循环，不能拿来预测某个真实模型如何切分任意单词。

切分是资源权衡，不是语义解析

合并常见片段，可以少用 token 表示常见文本；把罕见内容拆得更细，则让有限词表能覆盖更大的字符串空间。同一段文本被切成 2 个 token 还是 8 个，会影响上下文窗口能容纳的文本量、每 token 的计算成本以及训练目标的边界。一个子词碰巧像词根，不能证明 tokenizer 真懂了这个词根；tokenizer 负责切分与编号，语义关系要由后续训练的模型表示出来。

2.2 词嵌入：把 token 映射成可学习坐标

编号只是页码，不含任何“意思”。于是有了 Embedding（嵌入）：一张可学习的查找表，行数是词表大小 V，列数是向量维度 d。把它记作矩阵 E ∈ R^(V×d)。token ID 为 i 时，模型取出第 i 行 E[i]；这就是查表，不需要真的创建一张几百万列的 one-hot 表再做乘法。换成数学写法，若 one-hot 行向量 eᵢ ∈ R^V 只有第 i 位为 1，则 eᵢE = E[i] ∈ R^d。

一个玩具例子：假设词表只有 [猫, 狗, 跑]，每个向量只有 2 维，嵌入表可能是 E = [[0.8, 0.1], [0.7, 0.2], [-0.2, 0.9]]。ID 为 1 的“狗”便查到第二行 [0.7, 0.2]。真实模型的词表和维度大得多，而这些行向量是训练参数：随机初始化后，模型通过训练目标和反向传播不断调整它们。

训练之后，向量会对任务有用，但不能把嵌入空间想成完美的字典：常见语境、训练数据、子词切分、目标函数都会影响坐标。意思或用法相似的 token 有时会靠近；这不是对每个词都成立的几何定律。传统静态词向量里常见“国王 − 男人 + 女人 ≈ 女王”这样的关系方向，值得作为线性结构的例子，却不是 Transformer 学习必须满足的恒等式：

两个实用性质

平移不变：softmax(z) = softmax(z + c)，因为分子分母的指数都会乘上同一个 eᶜ。实际计算常先减去最大分数，避免指数溢出，例如对 [1000, 999] 先减 1000，再算 [0, −1]，概率不变。温度控制尖锐度：softmax(z/T) 中温度 T>0 小于 1 时分布更尖，大于 1 时更平；这不是改变相对排序，而是改变概率集中程度。

概率是什么意思，分数不是什么意思

Softmax 概率表示：在当前模型、当前上下文和词表定义下，预测分布把多少质量分给每个候选 token。它不自动等于现实世界事实为真的概率，也不保证经过统计校准。Greedy 解码取最大概率 token；采样则根据整组概率抽取 token。这两种选择策略使用同一分布，却可能给出不同文本；详见推理章节。

Transformer 里常见两种 Softmax 语境：① 注意力层对每个 Query 的一行分数做 Softmax，把它变成“从可访问位置取信息”的权重；② 输出层对词表 logits 做 Softmax，得到“下一个 token”的概率分布。两者都用同一公式，但分数来自不同地方，维度也不同。注意力内部可对被屏蔽的位置先加 −∞，Softmax 后其权重便为 0；第 5 章先介绍因果掩码，第 9 章再完整追踪训练时的信息流。

注意

Softmax 在 Transformer 里出现两次：① 注意力内部，把"Query-Key 匹配分数"转成"注意力权重"；② 输出层，把 logits 转成"下一个 token 是某某"的概率。两处公式相同，但分数来源和含义不同。

嵌入不是死的字典：误差怎样传回查找表

查表看起来像离散操作，但取出的那一行是连续参数，可以接收梯度。若 token ID i 的嵌入向量是 E[i]，损失对这个向量的梯度会传回嵌入矩阵第 i 行；同一个小批次里若该 ID 出现数次，这些出现位置对该行的梯度会累加。直觉上，训练不断问：“让这个 token 的起点表示朝哪个方向微调，能让整体预测损失变小？”优化器按梯度更新它。未出现在输入中的行，通常没有来自这条查表路径的梯度；但若输入、输出嵌入共享权重，某一行也可能通过输出投影收到梯度，权重衰减等机制也会影响参数。要记住这是参数学习，不是给每个 token 手写一条永久固定的词典定义。

从数学上，嵌入查表可看成 one-hot 向量乘矩阵：x=eᵢE。反向传播时，一次输入位置只选中 one-hot 的第 i 项，因此相应梯度被路由到 E 的第 i 行。实现通常使用索引查表与稀疏/聚合梯度，而不会真的创建长度等于词表大小的 one-hot 向量；两种写法描述的是同一线性选择。

查看答案

常见问题 FAQ · 从文字一路追到向量

本章最容易混在一起的是“文本片段、token ID、输入嵌入、上下文表示和输出概率”。下面沿着真实计算顺序逐一拆开。

Token ID 是不是所有模型都通用的“词典编号”？编号大小有意义吗？

不是通用编号，数字大小也没有词义。Tokenizer 会按自己的词表把输入片段映射到整数 ID；不同模型可能使用不同的切分规则、词表和编号，即使表面上看到同一个词，ID 也可能不同。ID 731 只是在某个特定词表里查找一项的索引，不表示这个 token 排在第 731 个语义位置，也不意味着它比 ID 730“更接近”ID 732。

实际送进模型的常是这些整数构成的张量，例如批量输入的形状为 [batch, sequence_length]。随后嵌入层把 ID 当作行号，从可学习矩阵中取出向量。换 tokenizer 或词表，模型输入的编号体系就变了；通常必须使用与模型配套的 tokenizer，不能只凭字符串猜 ID。

为什么 tokenizer 不直接“一词一个 token”？一个汉字或单词会被拆开吗？

token 不等于自然语言里的词。现代 tokenizer 常采用子词或字节级方法，在常见片段、罕见新词和词表大小之间折中。常见词可能整体成为一个 token；生僻词、拼写变化、带空格的片段或中文词语则可能被拆成几个子词、字或字节片段。具体切法取决于模型的 tokenizer，不能假定一眼看见的“词”就是一个 token。

这种设计能让有限词表组合出训练中少见的新字符串，避免每个罕见词都必须单独占一个词表条目。代价是不同语言和文本类型的 token 数不同：同一句话对两个模型可能有不同长度，token 长度也不等于字符数或词数。上下文窗口通常按 token 计，估算可输入内容时应使用对应 tokenizer 实际计算。

同一个 token 的嵌入向量既然固定，模型怎样分辨它在不同语境里的意思？

查表得到的初始 token 嵌入相同，但经过网络后的上下文表示可以不同。例如“苹果手机”与“苹果落地”中的“苹果”，在嵌入查表时会从同一行取得起点向量；位置表示加入后，注意力层还能分别读取“手机”和“落地”等周围 token，前馈层再继续变换。层层处理后，两处“苹果”的隐藏表示通常会受到不同上下文影响。

因此要问清楚“词向量”指哪一阶段：它可能指嵌入表中的初始向量，也可能指某层输出的上下文隐藏状态。前者主要由 token ID 决定；后者还依赖同一序列里的其他 token、位置、掩码、层数和模型参数。上下文表示更灵活，但它仍是网络中的数值状态，不是对词义的人工词典注释。

嵌入查表看起来是离散操作，梯度怎样训练嵌入矩阵？

把嵌入表记为 E∈ℝ^{V×d}，其中 V 是词表大小、d 是向量维度。输入 ID 为 i 时，查表返回第 i 行 E[i]。数学上等价于用 one-hot 向量 eᵢ 左乘矩阵：eᵢE=E[i]；程序通常直接做索引查表，不会真的创建一个很长的 one-hot 向量。

虽然“选择哪一行”是离散的，被选中的行本身仍是连续可学习参数。损失对这行向量的梯度会传回嵌入矩阵，并由优化器更新；若同一 token 在批次中多次出现，相应梯度会按实现累积。未被输入选中的行通常没有这条输入查表路径的梯度，但若输入嵌入与输出投影权重共享，或使用权重衰减等优化机制，其他路径也可能影响它。

Softmax 概率究竟表示什么？为什么数值实现要减去最大分数？

它表示模型对当前候选集合的归一化分配。在输出层，Softmax 把词表 logits 转为在该上下文和该词表下各 token 的预测分布；在注意力层，它把可访问位置的匹配分数转为读取 Value 的权重。它不自动代表事实为真的客观概率，也不保证统计校准；注意力权重同样不是对“理解程度”的直接量尺。

计算 exp(zᵢ) 时，较大的正 logits 可能导致浮点溢出。利用平移不变性，把整组分数减去最大值 m：softmax(z)=softmax(z−m)。此时每个指数的输入都不大于 0，最大项指数为 1，从而大幅降低溢出风险。训练时交叉熵通常直接接收 logits，由框架内部以 LogSumExp 等稳定方式完成运算；遇到被掩码的位置，还需在 Softmax 前正确屏蔽，否则它会错误地分到概率质量。

Chapter 03 · 打地基

Seq2Seq 与它的瓶颈：Transformer 为什么必须诞生

要理解一项发明，先理解它要消灭的痛苦。2017 年之前，机器翻译的世界是什么样子？

3.1 编码器-解码器：一个"压缩再解压"的世界

一种经典机器翻译方案叫 Seq2Seq（sequence-to-sequence，序列到序列）。下面描述的是早期的“固定上下文向量”版本：一个循环神经网络（RNN）读源句，另一个 RNN 写目标句。它是理解历史瓶颈的好起点，但不能代表所有 Seq2Seq——后来加入注意力的版本会保留并访问编码器每个位置的状态。

编码器（Encoder）逐词阅读源句

“我 爱 学习” → 每读一个 token，就用当前输入和上一步隐藏状态更新自己的隐藏状态。

用最后状态概括源句

早期基线把编码器读完后的状态作为固定长度上下文向量 c，常用它初始化解码器。维度固定（例如 512），不会随源句增长。

解码器（Decoder）逐步生成目标句

从起始符开始，每一步根据上下文和已生成 token 预测下一个 token，直到输出结束符（EOS）。

用符号把“读”和“写”说得更精确。对长度为 n 的源序列 x₁,…,xₙ，普通单向 RNN 编码器每步计算 hᵢ=f(hᵢ₋₁,xᵢ)，然后把最后状态 c=hₙ 交给解码器。普通 RNN 单元的一个示意写法是 hᵢ=tanh(Wₓxᵢ+Wₕhᵢ₋₁+b)；LSTM/GRU 会用门控与额外状态，表达式不同，但“下一步依赖上一步”的顺序特性相同。解码器在目标位置 t 根据上一步状态、上一个目标 token 和上下文，得到对词表的概率分布 p(yₜ | y₁,…,yₜ₋₁,c)。

于是整句目标概率按链式法则分解为 p(y₁,…,yₘ | x)=∏ₜ p(yₜ | y₁,…,yₜ₋₁,c)。这不是假设每个目标词互相独立，恰恰相反：第 t 步可以依赖前面已生成的目标词。训练时通常有正确目标序列可用，解码器可把正确的前一个目标 token 输入下一步（teacher forcing），并用交叉熵监督当前位置；推理时没有正确答案序列，只能把自己上一步生成的 token 接回模型。这个“训练时真值、推理时模型输出”的差别会影响错误如何向后传播，后续章节会再展开。

3.2 两大致命伤

致命伤 ① · 信息瓶颈

在这个早期基线中，无论源句是 5 个还是 500 个 token，编码器的最终隐藏状态维数都相同，所有源端信息都要经由这个固定大小的向量传给解码器。句子越长，向量越难保留所有细节；解码时也没有单独的源词状态可查。这是经典“固定长度上下文”瓶颈。注意：后来带注意力的 Seq2Seq 不再只依赖这一瓶颈向量，它保留编码器各位置的状态，让解码器在每一步按需读取；所以不应把这条批评泛化成“所有 RNN Seq2Seq 都把整句塞进一个向量”。

瓶颈 ② · 难以沿序列并行

RNN 的隐藏状态满足递推 hₜ = f(hₜ₋₁, xₜ)：必须先算出第 t−1 步，才能得到第 t 步的状态。对同一条序列中的时间步，这形成真正的数据依赖。因此，RNN 训练虽能并行处理批次中的不同样本、也可并行做单步矩阵运算，却难以同时算出一条长序列的所有状态。GPU 擅长大规模并行，这种时间步串行会限制吞吐量。

还有一项相关困难常被“记忆短”这句话掩盖：训练 RNN 时，较早时刻的误差要沿时间链反向传播（BPTT）。概念上，远处梯度包含多步局部导数的连乘；若这些变换反复把梯度缩小，信号会逐步消失，若反复放大则可能爆炸。梯度消失让模型难以用远处误差教会早期状态保留有用信息。LSTM、GRU 用门控路径改善长程信息和梯度传递，但它们没有消除“第 t 步要等第 t−1 步”的依赖；带注意力的 RNN 则给目标位置到源位置增加一条可学习的直接读取路径，缩短部分信息/梯度路线。Transformer 的自注意力也让两个位置可在一层中直接交互，但长距离连接是否学得好仍取决于数据和优化，并非自动解决一切。

把“串行”画成依赖图：每一步到底在等谁？

用 4 个输入位置看数据依赖。对一个单向普通 RNN 来说，位置 4 的隐藏状态要等位置 3，位置 3 又要等位置 2，依此类推。下面左图中的横向箭头代表“必须先算左边状态”，不代表信息只能沿一个方向流动；双向 RNN 会另外反向读取，但每个方向内部依然要按顺序递推。右图则画一个 Transformer 编码器层：每个输出位置可以从所有输入位置取信息，四行输出可由矩阵运算批量计算；底部小矩阵另示自回归解码器的因果约束。

要从图里读出两个不同结论：第一，Transformer 可以并行计算一层内多个位置的注意力结果，因为它不需要先得到 h₁ 才能得到 h₂；但是每层仍依赖前一层的输出，因此深度为 L 的网络仍按层推进。第二，全连接并非任何场景都正确：双向编码器通常允许读完整句，而自回归解码器必须屏蔽未来。因果矩阵中 Q₂ 可读 K₁ 和 K₂，不能读 K₃、K₄；实现通常在 Softmax 前把不允许的位置加上极大的负值（概念上是 −∞），从而令概率为零。

计算代价也不能概括成“Transformer 更快”。长度为 n、隐藏宽度为 d 的标准全注意力，每层含有约 n²d 量级的注意力交互计算，朴素实现还会保存 n×n 的分数/权重；Q/K/V 投影和前馈网络本身也有成本。RNN 的同一序列上存在 n 步串行依赖，单向递推常有约 nd² 的矩阵运算量。Transformer 以更多成对交互换取高并行度，序列很长时平方成本会成为负担；FlashAttention 等算法可减少读写和避免物化完整注意力矩阵，但并不会把精确全注意力的所有两两交互变成线性数量。硬件、批量大小、序列长度和实现共同决定吞吐量。

第一类瓶颈的关键缓解发生在 RNN 时代内部。Bahdanau、Cho 与 Bengio（2014 年提出、2015 年发表）的神经机器翻译工作，以及 Luong 等人 2015 年的研究，引入了不同形式的注意力：解码器每生成一个目标词，就根据当前状态对编码器各位置的隐藏状态打分、归一化，再加权汇总。模型不再只盯着一个最终向量，而能按当前翻译步骤回看相关源词。“注意力”一词由此进入序列学习主流，但当时它仍配合 RNN 工作；读源句和逐词生成译文的递推依赖仍在。

Bahdanau 加法注意力的一种常见写法是：eₜᵢ = vₐᵀ tanh(Wₛ sₜ₋₁ + Wₕ hᵢ)，再对源位置 i 做 αₜᵢ=softmaxᵢ(eₜᵢ)，最后算 cₜ=Σᵢ αₜᵢhᵢ。其中 sₜ₋₁ 是解码器当前状态，hᵢ 是编码器位置 i 的状态；Wₛ 与 Wₕ 把两种来源投影到同一个比较空间，vₐ 将匹配特征压成标量分数。注意力上下文 cₜ 因目标位置 t 而变化：翻译目标的不同词时，模型可以重新分配对源句各位置的权重。若“我 爱 学习”这三个位置的权重暂取 [0.1,0.7,0.2]，就有 cₜ=0.1h我+0.7h爱+0.2h学习；这组数字仅作演示，不能当作实际模型测得的对齐结果。加法注意力不是 2017 Transformer 里缩放点积注意力的同一个打分公式，但两者都用“查询/状态与一组可读表示匹配，再加权汇总”的通用思路。

原始资料：Bahdanau、Cho 与 Bengio，Neural Machine Translation by Jointly Learning to Align and Translate；Luong、Pham 与 Manning，Effective Approaches to Attention-based Neural Machine Translation；Vaswani 等，Attention Is All You Need。

3.3 石破天惊的一步：既然注意力这么强，还要 RNN 干什么？

Vaswani 等人的 2017 年论文把“注意力”从 RNN 的补充机制提升为序列建模核心。理解它的关键推理可以概括为：

Attention Is All You Need

用今天的话概括：「注意力可以让位置之间交换信息；RNN 则用循环递推来传递位置次序。若显式提供位置线索，并用掩码约束未来信息，就能移除循环，把整段序列的表示交给注意力层和前馈层并行计算。」这是理解论文设计的简化表述：注意力不自动知道顺序，所以论文加入位置编码；自回归解码器在训练中用因果掩码，不能偷看目标未来 token。

并行的具体含义是：在编码器（输入已知）中，所有 token 位置可同时参与同一层的矩阵计算；自回归解码器训练时已知完整目标序列，可将右移后的目标 token 一次输入，并用因果掩码训练所有位置。但推理生成时仍须逐 token 进行：要先采出下一个 token，才能把它作为后续步的上下文；缓存 Key/Value 可省去重复计算，却不会让尚未生成的未来 token 凭空出现。并且全注意力通常要构造与序列长度平方成比例的分数矩阵，序列越长，算力和内存成本也会明显增加。Transformer 改善了并行计算路径，同时带来了自己的计算与内存权衡。

历史结果也应准确陈述：在 Vaswani 等人的 2017 年论文里，Transformer Big 在 8 张 NVIDIA P100 上训练约 3.5 天，在 WMT 2014 英德、英法测试集分别报告 28.4 和 41.8 BLEU，并达到当时的领先水平。论文还报告了 Transformer Base 在 8 张 P100 上训练约 12 小时。这些数字属于特定数据集、配置与评测方法，不宜泛化成所有模型都“从几周缩短到几天”；它们说明的是该架构在当时的并行训练效率与翻译表现。

训练并行 ≠ 生成并行

用文字接龙想一想：训练时正确答案整串都在，模型可以同时学习“第 1 位该预测什么、第 2 位该预测什么……”；推理时答案未知，模型只能先生成一个 token，再接着生成下一个。因此 Transformer 的“并行”优势主要体现在处理已知序列和训练阶段，不表示聊天回复一次性从天而降。

查看答案

一个 Seq2Seq 翻译模型，从源句到译文的完整流程是什么？

可以把它想成“先读完源句，再按目标语言的顺序写译文”。例如输入 She reads books.：首先 tokenizer 把源句切为 token ID，嵌入与位置表示形成输入序列；编码器经过多层自注意力和前馈网络，为每个源位置计算上下文表示。与把整句压成唯一向量的早期模型不同，标准 Transformer 编码器会保留一串源位置表示。

目标端训练时，把正确译文前面加起始符 <BOS> 并整体右移，作为解码器输入；解码器的因果自注意力只看当前位置之前的目标前缀，再通过交叉注意力读取编码器的源表示。每个目标位置经输出投影产生词表 logits，与对应的下一个正确 token 计算交叉熵。推理时没有正确译文可右移，模型从 <BOS> 开始生成一个 token，把它追加到前缀后，再生成下一个，直到输出 <EOS> 或达到长度上限。编码器通常对源句只计算一次，解码器则逐步运行。

“瓶颈向量”具体卡在哪里？后来加上注意力后完全消失了吗？

早期固定上下文向量 Seq2Seq 会让编码器逐步读入源句，并把最后的隐藏状态当成整句摘要；解码器只能依赖这份固定维度的摘要开始生成。源句越长，需要保留的信息越多，却都必须挤进一个大小不随句长增长的状态里，较早的细节更容易难以传到输出端。这就是固定向量瓶颈的来源。

Bahdanau 等注意力式 RNN 让解码器在每个目标步根据当前状态，重新对编码器各位置的隐藏状态加权读取，缓解了把所有信息塞进最终状态的问题。Transformer 编码器—解码器也保留整串编码表示，并通过交叉注意力读取它们。注意力减轻了这个特定的信息通路瓶颈，但不会让表示容量无限：源端长度、隐藏维度、模型学到的读取方式和计算预算仍有限。

解码器的自注意力和交叉注意力各自看什么？为什么需要两种？

解码器自注意力处理“已经写出的目标前缀”，交叉注意力处理“源句提供的内容”。在生成目标句的第 t 步，因果自注意力让当前位置读取此前目标 token，帮助模型维持目标语言的语法、上下文和已生成内容；因果掩码禁止它偷看尚未生成的右侧 token。

交叉注意力则以解码器当前表示产生 Query，以编码器各位置的输出产生 Key 和 Value。这样每个目标位置都能按需寻找源句信息，例如生成一个译词时读取与之相关的源词或短语。源句表示一般在解码各步重复供交叉注意力查询。两种注意力的输入来源不同、职责不同，不能把它们都笼统地理解成“再看一遍自己”。

Teacher forcing 是什么？训练时和真正翻译时，解码器输入有什么不同？

训练时目标译文已知，因此常用 teacher forcing：把正确目标序列右移后喂给解码器。例如目标为 我 喜欢 猫 <EOS>，输入可为 <BOS> 我 喜欢 猫，同一位置的输出分别监督模型预测 我 喜欢 猫 <EOS>。因果掩码保证第 t 个位置只能看见目标前缀；即使整句并行输入，也不会泄漏后续正确答案。

推理时正确目标未知，只能先用 <BOS> 预测第一个 token，再把模型实际选出的 token 放进前缀预测下一项，所以生成过程存在逐步依赖。训练时总是接收正确前缀、推理时接收自己生成的前缀，可能带来误差累积或训练—推理差异；但 teacher forcing 能让许多目标位置在训练时并行计算，是常见而有效的训练方式。

既然 Transformer 的位置可以并行，为什么翻译生成还要一个 token 一个 token 地等？

并行能力取决于待计算位置的输入是否已知。训练时源句和正确目标句都已在数据中，右移后的目标序列可一次送入网络；因果掩码只改变哪些位置允许互相读取，并不妨碍矩阵同时计算各个目标位置。编码器的源句位置也能在同一层并行处理。

生成时，第 t+1 个目标 token 依赖第 t 步模型选出的结果。除非先知道未来 token，否则就无法形成未来步骤的正确输入，因此自回归解码必须依次前进。缓存此前的 Key/Value 可以避免每一步重复计算完整前缀，提升效率，但不能让尚未生成的目标内容提前确定。

Chapter 04 · 注意力

注意力机制：查字典的艺术

全书的心脏从这里开始。Query、Key、Value 三个字母，是理解一切现代大模型的钥匙。

4.1 一个贯穿全书的场景

想象你在一个巨大的图书馆里查资料。你脑子里有个问题（"它指的是谁？"），每本书的书脊上贴着标签，书里有具体内容。你的查书过程分三步：

你带着问题 —— Query（查询）

你的问题本身："这里的主语是谁？" 它是一个向量，代表你当前的需求。

每本书的书脊标签 —— Key（键）

标签用来"被匹配"。你把问题和每个标签比对相似度，得到"这本书有多相关"。

书里的内容 —— Value（值）

真正要取走的东西。相关度高的书，多摘抄一些；不相关的，直接略过。

最终收获 = 按相关度加权的内容混合

你不是只拿走一本书，而是把每本书的内容按"相关度份额"调配成一杯鸡尾酒。

类比 · 软查表

传统字典查询是"硬"的：键完全匹配就返回，不匹配就什么都没有。注意力是"软查询"：每个 Key 都匹配一点点，匹配度决定你拿走对应 Value 的多少。因为点积、Softmax 与加权求和可微，任务损失能够沿着计算图反向传播，训练 Query/Key 投影的匹配方式和 Value 投影的内容表示。可微与并行计算让这种机制适用于多种学习任务，但它不保证每次都找到人类期待的关联；效果仍取决于训练数据、目标函数和模型设计。

4.2 Q、K、V 从哪里来？——三个可学习的"投影"

回到我们的句子："那只小猫追着毛线球跑过客厅，它终于累了。" 每个词都已经有了嵌入向量 x。现在，模型对每个词做三次线性变换（三个可学习的权重矩阵），生成三个角色：

式 4-1

为什么要投影，不直接用 x？因为"我是谁"和"我想找什么"和"我能提供什么"是三件事。比如代词"它"：作为内容（Value）它提供的信息很弱；但作为提问者（Query），它的查询需求极强——"我急切地想知道我的先行词是谁"。三组矩阵 WQ、WK、WV 让模型能把这三种身份解耦，而且它们全是训练学出来的。

角色生活类比数学身份回答的问题
Query（查询）你脑子里的问题q = x·WQ"我在找什么？"
Key（键）书脊上的标签k = x·WK"我是什么？（用来被检索）"
Value（值）书里的内容v = x·WV"如果被关注，我贡献什么？"

把这张表落到矩阵计算上：设输入有 n 个 token，每个 token 当前宽度 dmodel，把它们按行堆成 X∈ℝn×dmodel。若这一步是自注意力，三组投影分别把 X 变成 Q、K、V；它们第一维仍是 n，因此每个位置同时提问、同时可被检索、同时准备一份内容。交叉注意力会改成 Q 来自目标序列、K/V 来自另一段记忆，但稍后的点积与加权和完全沿用同一规则。

注意行向量写法和列向量写法只影响矩阵乘法左右顺序。本讲义统一写行向量 q=xWQ，因此若 x 是 1×dmodel，WQ 是 dmodel×dk，q 就是 1×dk。有些教材把向量写成列，公式会写成 q=WQx；只要维度互相匹配，表达的是同一件事。

4.3 一次完整的注意力计算，手算版

我们把"它"这个词的注意力算一遍。为可读性用 2 维玩具数字（不少模型每头宽度在 64～128 左右，但具体配置差异很大）：

第 1 步 · 算分数：Query 和每个 Key 做点积

"它"的 q = [1.0, 0.5]。"小猫"的 k = [0.9, 0.4]，"毛线球"的 k = [0.1, 0.8]，"客厅"的 k = [0.0, 0.3]。

分数：小猫 1×0.9+0.5×0.4 = 1.10；毛线球 = 0.50；客厅 = 0.15。

第 2 步 · 缩放：除以 √dk

dk=2，√2≈1.41。分数变为 [0.78, 0.35, 0.11]。为什么除？马上讲。

第 3 步 · Softmax 变成权重

softmax([0.78, 0.35, 0.11]) ≈ [0.462, 0.302, 0.236]。"小猫"拿到约 46% 的注意力份额。计算方法是先取指数，再除以三者指数之和。

第 4 步 · 加权求和 Value

输出 ≈ 0.462·v小猫 + 0.302·v毛线球 + 0.236·v客厅。"它"的新表示较多吸收了"小猫"的信息，同时仍混入其余上下文；具体语义由训练学到的 Value 投影决定。

最后一步把所选 Value 混成一个上下文向量；它是注意力子层在"它"这个位置写出的信息，不等于整个 Transformer 最终的词表示。实际层通常再经过输出投影、残差连接和归一化。训练会使这些分量有助于下游预测，但注意力权重本身不保证等于语言学重要性或模型的解释。

4.4 著名的公式，现在你可以读懂它了

式 4-2 · 全文最重要的一行

上标 T 表示转置：把矩阵的行和列互换。逐个符号拆解（设序列长度 n，Q/K 维度 dk，V 维度 dv）：

符号形状含义
QKᵀ(n×dk)·(dk×n) = n×n每个 Query 对每个 Key 的匹配分数矩阵（不是单位向量余弦相似度的保证）
÷√dₖ逐元素缩放，防止 Softmax 饱和（见下）
softmax(·)对每一行每行变成一个概率分布："我"对全句的注意力份额
·V(n×n)·(n×dv) = n×dv每个位置输出 = 全句 Value 的加权平均
为什么要除以 √dₖ？——论文里最容易被忽视的神细节

若 q、k 的各维近似独立、均值 0、方差 1，则每个乘积 qiki 的方差约为 1，点积 q·k 是 dk 项之和，方差约为 dk、标准差约为 √dk。维度增大时，未缩放的分数更容易拉开；进入 Softmax 后分布可能过尖，非最大项对应的梯度会变小，优化可能更困难。除以 √dk 把分数的典型尺度控制在较稳定的范围。这是基于初始化统计的动机，不是说每个分数必为 ±√dk，也不是说缩放能保证梯度永不消失。

为什么叫"Scaled Dot-Product Attention"

加法注意力（additive，Bahdanau 式）与点积注意力都能学习 Query–Key 的匹配分数，但函数形式并不相同。点积形式可直接批量写成矩阵乘法，适合 GPU 的 GEMM 优化；在论文设定下，它以更少的串行运算获得有竞争力的效果。硬件友好是这项选择的重要工程理由。

4.5 把手算题再走一遍：从分数到向量

刚才的玩具例子给了"它"的查询 q=[1, 0.5]，并给三个候选位置的小猫、毛线球、客厅各一把键。以小猫为例，q·k小猫 = 1×0.9 + 0.5×0.4 = 1.10；再除 √2 得 0.778。三个缩放分数约为 [0.778, 0.354, 0.106]。稳定实现会先减去最大值 0.778，再算指数：[1, e-0.424, e-0.672] ≈ [1, 0.654, 0.511]，除以和 2.165 后得到 [0.462, 0.302, 0.236]。这与直接对原分数取 softmax 相同，只是数值更安全。

接着，注意力权重选择的是 Value，而不是 Key。假设 v小猫=[1,0]、v毛线球=[0,1]、v客厅=[-1,0]，那么加权结果约为 [0.462−0.236, 0.302]=[0.226,0.302]。它没有"挑出一个词"，而是把三个内容压成连续向量。真实模型里的 Value 维数通常远大于 2，投影矩阵也会在训练中改变这些方向。

手算检错清单

先确认 q 与每个 k 的维数相同；再对每一行分数分别做缩放和 Softmax；权重行和应约为 1；最终输出维数跟 v 的维数一致，而不是跟 k 的维数自动相同。若 Q 长度是 nq、K/V 长度是 nkv，权重形状是 nq×nkv，输出形状是 nq×dv。

4.6 形状追踪：一批句子怎样并行算

手算把一个 Query 单独拿出来；模型实际会把整批 token 一起做矩阵运算。先忽略多头，设批量大小 B、序列长 n、输入宽度 d、键宽 dk、值宽 dv：

张量形状谁和谁相乘
输入 X(B,n,d)每个 batch 的 n 个位置，各有 d 个特征
Q = XWQ(B,n,dk)最后一维由 d 投影到 dk
K = XWK(B,n,dk)KT 在最后两维交换，成为 (B,dk,n)
S = QKT/√dk(B,n,n)每个 Query 对本句 n 个 Key 打分
A = softmax(S)(B,n,n)沿 Key 位置一轴做行归一化
O = AV(B,n,dv)(B,n,n)·(B,n,dv)

批次维 B 只是把互不相关的句子并排处理，不会让第 1 个句子的 Query 去查看第 2 个句子的 Key。实现中批次轴常通过广播规则省略书写；真正的矩阵乘法发生在最后两个维度。若做交叉注意力，Query 长度可为 m，Key/Value 长度可为 n，于是 S 是 (B,m,n)，AV 是 (B,m,dv)。这个不等长特例会在第 8 章的编码器—解码器桥梁里再次出现。

4.7 注意力为什么能学：权重不是人工写死的

对某个 Query 行，先算分数 sj=q·kj/√dk，再算 aj=exp(sj)/Σrexp(sr)，最后 o=Σjajvj。Softmax 是平滑可微的：某个键的分数略微升高，它的权重就会连续增加；梯度可以从任务损失穿过加权和、Softmax 和点积，一直回到 WQ、WK、WV。因此模型不是先天知道"代词该看名词"，而是在大量预测误差的反馈中逐渐调整检索方式。

可以更精确地看分数如何改变输出。对某个分数 sj 求导，有 ∂o/∂sj = aj(vj − o)。直觉是：提高 j 的分数，会把一点权重从当前混合结果 o 挪向 vj；若 vj 与 o 很相似，这次挪动几乎不改变输出；若差异大，输出会沿着它们的差向量移动。这个式子说明“权重变大”不等价于“最终预测一定变好”，好坏还要看损失函数对输出方向的评价。梯度下降会把这种评价反馈到 q/k 投影，使匹配分数逐渐服务于训练目标。

一个两值标量例子：令 v1=0、v2=10，权重分别为 0.8、0.2，则输出 o=2。若稍微提高第二个分数，Softmax 会把部分权重转给 10，输出向 10 移动；若两个 Value 都是 2，提高任一方分数都不会改变结果。实际 Value 是高维向量，损失对输出各方向的梯度决定更新方向。

这也解释了注意力的边界：权重 aj 只表示这一层、这一头、这一 Query 对各 Value 的混合比例。Value 内容、输出投影、残差路径和后续层都会影响最终预测。把某格的 0.8 直接翻译成"模型有 80% 把握这两个词有语法关系"，超出了公式能支持的结论。

4.8 掩码：哪些格子允许参与这次查找？

掩码（mask）不是另一个注意力公式，而是对分数矩阵中某些格子施加“不可访问”的限制。设一个 Query 对 4 个 Key 的分数是 [1.2, 0.4, 2.0, -0.5]，若第 3 个位置是 padding，就在 Softmax 前把该格改成负无穷：[1.2, 0.4, −∞, −0.5]。指数化以后 exp(−∞)=0，因此 padding 位置权重为 0；剩下三格重新归一化，非 padding 权重仍合计 1。

常见限制有三类：padding mask屏蔽批次补齐出来的空位；causal mask屏蔽自回归预测的未来 token；任务/结构 mask可按窗口、区块或跨模态规则限制连接。掩码通常与位置轴广播到每个头、每条样本，最终目标是让禁止的位置在 Softmax 中拿到零权重。不同框架会用布尔值、0/负无穷加法偏置或专用 kernel 表达，读代码时要核对其 true/false 含义和屏蔽符号约定。

实现边界条件

一行若把所有 Key 都屏蔽，直接对全负无穷做 Softmax 会出现未定义的 0/0 或 NaN；健壮实现会避免这种全遮挡行，或专门定义安全行为。做 padding mask 时也要确认被屏蔽的是 Key 列；padding Query 行如何处理则由任务与实现决定。掩码解决的是“能看谁”，不负责自动告诉模型“应该学会什么”。

4.9 常见疑问门诊

Q1：Q 和 K 明明都是同一批词变来的，点积为啥有意义？

正因为 WQ ≠ WK，两个矩阵把词向量投进了不同的空间：Q 空间回答"找什么"，K 空间回答"是什么"。训练会调整这两组投影，让"该互相找到的词对"在两个空间里恰好方向一致。你可以理解为：模型在学习一套"问答匹配的编码方式"。

Q2：注意力权重一定等于"语言学上的重要性"吗？

不一定。注意力是信息路由机制，不是解释机制。它搬运动的是对"预测下一个词"有用的信息，未必符合人类语法直觉。第 11 章讲可解释性研究时会再回到这个话题。

Q3：每个词都要和每个词算分数，是不是 O(n²)？

密集注意力的 QK 与 AV 交互计算随序列长度平方增长。朴素实现会物化并保存完整的 n×n 分数/权重矩阵，产生二次规模的中间显存；FlashAttention 通过分块和在线归一化避免存下整张矩阵，但不会消除密集注意力的二次计算量。滑动窗口与稀疏注意力会改变允许交互的位置，属于不同的注意力模式。

本章常见问题 FAQ · 把分数、权重和形状分清

注意力权重是“概率”吗？模型是不是在选一个词？

对固定 Query 的一行而言，Softmax 后各权重非负且和为 1，因此可以按数学形式把它看成在候选 Key 位置上的离散分布；但模型并没有必须抽取一个位置。通常所有 Value 都按权重参与加权和，例如权重是 [0.6, 0.4] 时，输出是 0.6v₁+0.4v₂，而非随机选 v₁ 或 v₂。更准确地说，它是这次读取中各候选 Value 所占的归一化份额。

Softmax 为什么按每个 Query 的一行做，而不是整张分数矩阵一起做？

QKᵀ 的第 i 行属于第 i 个 Query，它列出这个 Query 对所有可见 Key 的分数。沿 Key 轴做 Softmax，才会让“位置 i 如何分配自己的读取份额”合计为 1；若把整张 n×n 矩阵摊平归一化，所有 Query 会争抢同一个总和，某行的权重就会受其他 Query 分数影响，语义也变了。批量实现要核对 Softmax 的轴：通常是 Key 位置轴，加入头与 batch 轴不改变这一点。

给一整行分数都加同一个常数，注意力会改变吗？

不会。对任意常数 c，softmax(s+c)=softmax(s)，因为每个指数都乘上相同的 exp(c)，分子分母会抵消。稳定计算因此常先减去该行最大分数：softmax(s)=softmax(s−max(s))，结果在数学上完全相同，却能避免指数过大溢出。实际浮点数有舍入误差，所以两种算法最后几位可能略有差异；减最大值是数值稳定技巧，不是额外训练出来的模型行为。

Query 与 Key 的宽度一定相同吗？Value 必须和它们一样宽吗？

Q 与 K 做点积，因此它们最后一维必须相同，通常都记作 dₖ；Value 的宽度 dᵥ只要求和注意力权重矩阵的 Key 轴对齐，最后输出宽度就是 dᵥ。若 Query 数为 n_q、Key/Value 数为 n_kv，则 Q:(n_q,dₖ)、K:(n_kv,dₖ)、V:(n_kv,dᵥ)，分数与权重为 (n_q,n_kv)，输出为 (n_q,dᵥ)。所以交叉注意力可处理长短不同的两段序列，且 dᵥ不必在数学上等于 dₖ。

关键洞察 · 词义不再是静态的

传统词嵌入（word2vec）一词一向量，多义词无解。自注意力让词义变成句子的函数：词的最终表示 = 自己的嵌入 + 上下文按注意力加权注入的信息。消歧、指代、长距离依赖，都是这一个机制的副产品。

5.5 为什么必须有顺序信息：置换等变性的直观证明

把整句话的行按同一个置换矩阵 P 重排。没有位置编码时，Q、K、V 也只会相同地重排：Q′=PQ、K′=PK、V′=PV。分数矩阵变为 Q′K′T=P(QKT)PT；对每行 Softmax 后仍是 P A PT，最终 O′=PAV。换句话说，输出的内容会跟着输入行一起换位置，计算本身没有线索说明哪一个原本是第 1 个词。这叫置换等变性：输入怎么重排，输出就以相同方式重排。

这和"置换不变"不是同一个词：模型没有把 token 顺序打乱后完全忘掉各行身份，而是没有内建出语序含义。位置编码、相对位置偏置、RoPE 或因果掩码等结构会破坏这种任意置换对称性，为模型提供顺序或可见性线索。位置编码也不会自动教会模型中文主谓关系；它只提供坐标，语言规律仍要从训练中学。

一眼看懂

把 "猫追球" 三个 token 当三张没有编号的卡片，裸自注意力只能比较卡片内容。给卡片编号，或规定只能朝左看，模型才知道它们处在不同位置。编号是线索，不是答案：同一词在不同位置仍须由上下文和训练目标共同解释。

5.6 从静态词嵌入到逐层上下文化表示

说 "bank" 的嵌入相同，是指同一个 token id 查到的词向量相同；嵌入层随后通常会把它与位置向量相加，所以两个句子的输入行已因位置和其他 token 不同而不同。进入自注意力后，"bank" 的 Query 与全句 Key 配对，混入相关 Value；经过多层以后，向量可以保留词形信息，同时编码上下文提供的语义线索。

同样要分清三件事：词表嵌入是参数表中的静态向量；某层隐藏状态是该位置当前的上下文表示；注意力加权和是子层产生的一部分更新。残差会把旧状态带到后续计算，所以不能把"注意力输出"简单等同为最终词义。不同模型、层和头会形成不同表示，歧义消解是整体网络与训练目标共同学出的行为。

本章常见问题 FAQ · 自注意力与“不能偷看未来”

训练时明明一次输入整句，因果注意力怎么保证没有偷看答案？

关键是两件事一起做：目标输入右移一格，且注意力分数用因果掩码遮住未来。若标签是 [I, love, learn]，输入是 [<bos>, I, love]；第 t 个位置只能读取当前输入前缀，负责预测右边那个标签。模型可以并行计算所有位置的矩阵，但第一个位置没有通向后续位置的注意力边，因此看不到 I、love。若忘了右移，当前位置可能直接复制它已看到的目标 token，训练任务就错了。

因果掩码为什么允许位置 i 看见自己？“预测下一个词”不是不能看到当前词吗？

位置 i 的输入本来就是已知前缀的一部分：例如喂入“我爱”，末位置“爱”的隐藏状态要预测下一个 token。它可以读取包括自身在内的全部已知前缀，不能读取目标未来。用零起始索引时，允许条件是 key 位置 j≤query 位置 i，保留矩阵的对角线和左下三角；“不看未来”不是“不能看当前输入”。答案 token 放在右移后的监督标签里，因此不会出现在该位置的输入中。

Padding mask 和 causal mask 是同一种限制吗？批次补齐后该遮哪一轴？

两者解决不同问题。Causal mask 按位置顺序屏蔽未来列，确保自回归因果性；padding mask 按样本真实长度屏蔽补齐出来的 Key 列，避免模型把虚构的 PAD 当作信息源。通常两种限制会合并到同一分数偏置中，再在 Softmax 前施加。padding Query 行的输出一般还会在后续忽略或屏蔽；若某行所有 Key 都被遮住，普通 Softmax 可能产生 NaN，因此实现必须保证有有效键或定义安全处理。

既然注意力要比较每一对词，自注意力是不是总要存一张 n×n 矩阵？

密集注意力逻辑上确实要计算每个 Query–Key 对，交互 FLOPs 随序列长度约按 n² 增长；标准教材实现还会显式保存分数或权重矩阵。FlashAttention 将计算分块并在线累计 Softmax，使完整 n×n 矩阵无需写入高带宽显存，显著降低中间显存和数据搬运，但密集两两交互本身并没有消失。窗口、块稀疏等方法则改变可连边集合，才可能减少需要计算的配对数量。

Chapter 06 · 注意力

多头注意力：一个评委不够，那就开个评审团

Multi-Head Attention = 多组 Q/K/V 投影并行打分，各看各的角度，最后汇总。这是"一个意思"的多种看法。

6.1 单个注意力头的盲区

单个注意力头可以把权重分给多个位置，但它每行只产生一套权重，再把多个 Value 压成一个加权和。在句子 "The animal didn't cross the street because it was too tired" 里，"it" 可能同时需要关于 "animal" 的指代线索、关于 "tired" 的语义线索、以及与 "cross" 的句法联系。单头必须把这些需求混进同一套权重与同一个向量；多头则能在不同投影子空间里形成多套混合，再拼接起来供后续层整合。评委团类比的重点是"多种视角并行"，不是单头只能选一个词。

类比 · 评审团

一场选秀，只请一个评委风险太大：他可能只看唱功。请八个评委——唱功、舞美、作词、舞台表现各一人盯着——最后合议，判断才全面。多头注意力就是给每个词配了 8 个（或 64 个、128 个）评委。

再用参数数目检查一次。这个小例中，每个头的 WQi 为 4×2，两个头合计 16 个 Q 权重；K 和 V 同理各 16 个。输出投影 WO 为 4×4，共 16 个权重，总计 64 个，恰好是 4dmodel2=4×16（未算偏置）。这与一个 4 维宽头的 Q/K/V/O 权重数量相同，但计算函数不一样：多头产生两套 Softmax 权重图，再把不同的内容通道交由 WO 组合。参数数量相同，不代表表示能力或注意力模式相同。

代价怎么算

若每头宽 d/h，所有头的分数与加权值计算约为 2n²d（忽略常数和 Softmax）；Q/K/V/O 四个稠密投影约为 4nd²。长序列 n≫d 时，n²d 交互项更醒目；大模型 d 很宽时，投影与 FFN 也占显著 FLOPs。比较模型不能只数头数，得同时看 n、d、头宽、层数及实现。

6.4 头会学出不同视角吗？可以，但不是预先指定的岗位

各头有各自的 Q/K/V 投影，所以优化有机会让它们形成不同的关联模式；可视化研究确实观察到一些头偏好近邻、分隔符或特定句法关系。但"第 1 头就是主谓头、第 2 头就是代词头"不是架构保证，功能会随模型、训练语料、层和上下文而变。不同头也可能学到相似模式，甚至某些头被删去时性能影响较小。因此，最好把评委团当成帮助理解并行子空间的类比，而不要把每位评委的专业写进解释。

同样，头数增加不等于能力必然增加。固定 dmodel 时，头越多，每头宽度越窄，单头能携带的特征也变少；头过少则可并行表达的注意力模式较少。工程上还要考虑 KV 缓存：标准多头注意力每个头都保存 K/V，推理长上下文时这笔内存成本很可观。多查询注意力 MQA 让多个 Query 头共享一组 K/V，分组查询注意力 GQA 则让一组 Query 头共享一组 K/V，用质量、吞吐与缓存大小的折中换更省显存的解码。

6.5 研究者们后来发现的事

可解释性研究曾在 BERT 等模型中观察到部分头偏向特定模式，例如跨句分隔符、近邻位置或某些句法线索；消融研究也发现，训练后的部分头可被移除而只造成有限损失。这说明头部有时冗余，但不意味着所有模型都能随意剪头而不掉性能。若要判断某个头是否重要，需要在目标模型与任务上做干预实验，而不是只看一张热图。

警惕 · 头不是越多越好

《Are Sixteen Heads Really Better than One?》（2019）证明：训练完后砍掉大部分头，性能下降有限——很多头是冗余的。后来的 GQA/MQA（第 11 章）干脆让多个查询头共享同一组 K/V，推理省显存。设计永远服务于约束。

本章常见问题 FAQ · 多个头怎样成为一个模型

头数 h 是谁决定的？模型会自己长出头，还是训练时自动选头数？

通常由模型设计者把 h 作为架构超参数指定；训练会学习每个头里的矩阵，却不会在标准多头注意力中自动增删头。设计时会一起选 dmodel、h、每头宽 dh、层数与 KV 头数，并比较验证集质量、吞吐、显存、延迟和目标硬件上的 kernel 效率。经典配置常令 dh=dmodel/h，以便 h 个头拼接后回到主干宽度；这要求能整除，但不是自然定律。头数加倍、每头变窄，和头宽不变、总内宽加倍，是不同实验，不能只看 h 判断模型更强。

每个头具体有哪些独立参数？它们怎样一起学会配合？

输入 X∈ℝB×n×d 会送给各头各自的投影：头 i 有 WQi∈ℝd×dₖ、WKi∈ℝd×dₖ、WVi∈ℝd×dᵥ（可另有偏置）。它们产生本头的 Q/K/V、Softmax 权重和输出；所有头输出拼接后再过共享的输出投影 WO。训练并没有给各头单独写“句法”“指代”标签：最终任务损失经整个网络反向传播，同时更新各头投影与 WO。因此头之间既有各自参数，也通过共同损失和后续共享计算协作。

第 1 头是不是天生负责句法，第 2 头负责指代？

不是。架构只规定每个头有一条独立的投影与注意力计算路径，没有把头编号绑定到某种语言学岗位。随机初始化、数据、损失、优化过程和其他头的状态共同影响它学到什么；研究者事后有时能发现某头偏好近邻、分隔符或某些句法关联，但这是一种依具体模型和输入而变的经验现象，不是写进代码的承诺。换训练种子、层、语料或模型，观察到的“职责”都可能变化；注意力图也不足以单独证明因果功能。

为什么常把 dmodel 平均分给 h 个头？每头宽度必须是 dmodel/h 吗？

在常见配置中取 dh=dmodel/h，是为了让 h 个 dh-维输出拼起来恰为 dmodel，再由 WO 映回残差流；这样改变头数时通常保持总投影宽度与主要参数量在相近预算内。它是方便的参数化与预算选择，不是点积注意力的数学要求：Q/K 必须同宽以便点积，Value 可有自己的宽度，而总头宽也可另行设计。若总宽固定，头过多会令单头空间变窄；头过少则可并行学习的匹配子空间较少，需通过实验权衡。

头会重复吗？剪枝和 GQA/MQA 到底省了什么？

会有部分头学到相近或可替代的行为；研究中通过消融发现某些已训练模型删去一些头，特定任务性能只小幅变化。但某头单独删掉影响小，不代表多头都无用，也不代表在另一数据、层或组合下仍冗余；头的相互作用与硬件实现都要实测。结构化剪头可以减少实际计算，前提是相应缩小投影并由高效 kernel 执行。GQA/MQA 是另一种设计：保留多个 Query 头，却让一组 Query 头共享较少的 Key/Value 头（MQA 是只共享一组），主要减少自回归解码时 KV cache 的体积和带宽；它们不等于把所有注意力头事后删掉，质量与速度仍需在目标场景评测。

Chapter 07 · 组装整机

组装 Transformer：位置、残差、归一化与前馈网络

注意力负责路由信息；位置线索让顺序可辨；残差与归一化帮助深层计算维持可用尺度；FFN 则逐位置变换特征。本章把这些积木放回一条真实的数据通路中。

7.1 位置编码：给词标上"门牌号"

先直面一个事实：没有位置线索时，自注意力无法知道词的顺序。把输入各行按某个排列重排，Q、K、V 也一起重排；注意力输出只会按相同排列移动。这叫置换等变性（permutation equivariance），不是输出完全不变，而是模型不知道重排前后哪一行原本在前。只有裸自注意力时，"狗咬人"与"人咬狗"缺少区分语序的线索。

对没有位置特征的双向自注意力来说，顺序线索需要由架构提供。2017 年原论文给输入加上正弦位置编码：为每个位置 pos 生成一个向量，不同维度用不同频率的正弦/余弦波：

类比 · 为什么是正弦？

一座钟用时针、分针、秒针共同编码时刻——每根针周期不同，组合后可帮助区分不同时刻。正弦位置编码同理：512 个维度像周期各异的指针，组成一串平滑变化的位置特征。更重要的是，固定偏移 Δ 对一对 sin/cos 分量的作用可写成线性旋转，因此相对偏移与绝对位置有规律的代数关系；这让模型有机会学习相对距离，但并不保证它自动掌握了所有相对位置任务。

位置向量和词向量直接相加（维度相同），一起送入第一层；从此以后，每层在相同的隐藏状态里同时处理词义与位置信号。不同模型选择不同位置机制：原始 Transformer 用固定正弦编码；BERT、早期 GPT 等用可学习绝对位置嵌入；RoPE 则按位置旋转 Q、K，使它们的点积带有相对位移结构。共同点是给注意力提供顺序线索，具体外推能力和长上下文表现仍需结合设计与训练评估。

用一个小维度检算公式，取 dmodel=4。前两维对应 i=0，分母是 100000=1；后两维对应 i=1，分母是 100001/2=100。所以 PE(0)=[0,1,0,1]，PE(1)≈[0.841,0.540,0.010,1.000]。同一个 token 若出现在这两个位置，输入分别是 e+PE(0) 与 e+PE(1)，不是两个不同的词表嵌入。小维度例子展示计算方式；真实 dmodel 下会有很多不同频率，位置编号通常也不只取 0 和 1。

为什么用成对 sin/cos？把位置从 pos 平移 Δ 后，一对坐标可由一个只依赖 Δ 的二维旋转矩阵得到：[sin(pos+Δ),cos(pos+Δ)] 是 [sin(pos),cos(pos)] 的线性组合。模型因此有机会用线性投影捕捉某些相对偏移模式。这里是“提供方便的代数结构”，并非证明任意 Transformer 一定能外推任意距离；训练长度、频率范围、位置插值方式和注意力结构都会影响实际表现。

7.2 残差连接：修一条信息高速公路

经典 Transformer 的每个子层外都有残差分支：输入 x 与子层变换相加，再进入归一化等后续运算。原论文是 Post-LN，可写作 LayerNorm(x + 子层(x))；现代常见 Pre-LN 写法为 x + 子层(LayerNorm(x))。因此“残差相加”是共同骨架，LayerNorm 的具体位置则因架构而异。加法要求两支形状兼容；FFN 内部升维后会投回残差流宽度再相加。

为什么这个加号如此重要

① 保留直达信息通路：子层学的是叠加到 x 上的更新，输入不会被单一路径覆盖。② 改善深层优化：若 y=x+F(x)，局部 Jacobian 是 I+JF，反向梯度除了经过 F 的路径，也有经过恒等映射的路径。③ 便于逐层修正：当理想变换接近恒等映射时，子层不必从零重建输入。不过残差不是梯度永不消失/爆炸的保证：很多层的 Jacobian 仍会相乘，归一化、初始化和学习率同样重要。

以宽度 d=512 为例，残差支路上的 x 与子层输出 F(x) 都必须是 (B,n,512)，才能逐元素相加。注意力内部每头可能只有 64 维，FFN 中途会扩到 2048 维，但它们都必须在返回残差加法前投回 512。加法不是拼接：第 j 个通道只与另一支第 j 个通道相加；若两支宽度不同，就得增加投影或重新设计块。

用极小的二维向量看 Post-LN 与 Pre-LN 的差别。令 x=[1,3]，LayerNorm 的 γ=[1,1]、β=[0,0]，忽略 ε，则均值为 2、标准差为 1，故 LN(x)=[−1,1]。再令子层 F(u)=0.5u：Post-LN 先算 x+F(x)=[1.5,4.5]，再归一化为约 [−1,1]；Pre-LN 算 x+F(LN(x))=[0.5,3.5]。两种排布都让 x 走残差支路，但子层看到的输入、LayerNorm 的位置和块输出数值都不相同。真实网络 γ、β 与 F 都可学习，例子只用于确认运算次序，不能用来比较哪种一定训练得更好。

可以把残差连接想象成写作的修订模式：每一层都会收到上一稿，同时可提交一个修订量；网络把稿件与修订量相加后交给下一层。它有助于信息和梯度穿过深层网络，但不能简单理解成每轮都保留了完整原稿的可读语义。

7.3 LayerNorm：让每个样本自带"标准刻度"

层归一化（LayerNorm）对每个 token 的隐藏向量沿特征维计算均值和方差，再标准化并施加可学习的逐通道缩放 γ、平移 β。这样一行隐藏状态就能在不读取同批其他样本的情况下获得稳定的尺度控制；它的作用不应简化成某一种单一的"内部协变量偏移"解释。

和 BatchNorm 的关键区别：对常规二维特征输入，BatchNorm 通常对每个通道汇总 batch 中样本统计；LayerNorm 则对每个样本的隐藏特征轴独立统计。NLP 张量有 padding、长度不一且 batch 可能较小，LayerNorm 的统计不依赖 batch 组成，训练与推理采用同一计算方式，因而很适合 Transformer 的 token 表示。

以某个 token 的向量 x=[2,0,−2,0] 为例，均值 μ=(2+0−2+0)/4=0，按这四个特征的总体方差计算 σ²=(4+0+4+0)/4=2。标准化后约为 [1.414,0,−1.414,0]（忽略 ε）；再逐通道乘 γ、加 β。ε 是很小的正数，防止方差接近零时除法不稳定。要记住：归一化轴是隐藏特征，不是句子中的 token 位置；每个位置各算一份均值和方差。

进阶 · Pre-LN 与 Post-LN 之争

原论文采用 Post-LN：LayerNorm(x + 子层(x))；常见 Pre-LN 写法是 x + 子层(LayerNorm(x))。Pre-LN 给跨层残差路径留下更直接的恒等映射，许多深层设置下优化更稳，但这不表示无需 warmup、初始化或合适学习率；不同归一化位置会改变梯度尺度和训练动态。RMSNorm 省去均值中心化，用均方根缩放并保留可学习增益，是一些 LLaMA 系列模型采用的替代方式。

常见误区 · LayerNorm 会把每层输出强行变成标准正态分布吗？

不会。它对单个 token 的隐藏维做中心化与方差缩放，然后施加可学习的 γ、β；有限维特征一般也不能据此称为严格的正态分布。归一化规范的是该位置内部的统计量，而不是训练数据整体分布，也不代表隐藏特征从此失去幅度信息，因为仿射参数和后续变换仍能调整尺度。

常见误区 · 残差加法等于把两个表示拼在一起吗？

不等于。逐元素加法把同一位置、同一通道上的两份数值相加，因此形状必须一致；拼接则增加通道宽度，后面通常要接投影。加法成本低且保留恒等路径，拼接能保留并列通道但会改变形状和参数量。Transformer 的标准残差是加法。

一个有用的功能分工是：注意力让位置之间交换信息，FFN 对每个位置分别做非线性特征变换。标准 Transformer 的 FFN 对所有位置共用同一组参数，但位置之间不在 FFN 这一步直接通信。研究者曾把 FFN 单元分析为知识关联的组成部分；这是一种有实验支持的理解方式，不等于模型全部事实都能定位到一个明确的"记忆库"。若 dff=4d 且使用两层稠密投影，FFN 约有 8d² 个权重；标准注意力的 Q/K/V/O 投影约有 4d²，因此这个配置下 FFN 参数约占两者之和的 2/3（忽略偏置和其他结构）。

7.5 把一个编码器块写成完整计算图

现在把前面三个零件放回一个块里。原论文采用 Post-LN，忽略 dropout 时可写成：U = LayerNorm(X + MultiHeadSelfAttention(X))，Y = LayerNorm(U + FFN(U))。每次加法的两边都是 (B,n,dmodel)。注意力内部短暂展开成每头的 Q/K/V 与 (B,h,n,n) 权重；拼头投影后回到 (B,n,dmodel)。FFN 内部先变成 (B,n,dff)，经过激活后再投回 (B,n,dmodel)。于是归一化后，下一层仍收到同样长、同样宽的残差流。

Pre-LN 则将每个子层改写为 U = X + MultiHeadSelfAttention(LayerNorm(X))，Y = U + FFN(LayerNorm(U))。无论 Pre-LN 还是 Post-LN，注意力负责跨位置路由，FFN 负责逐位置变换，残差让两类子层的更新回到共同表示流；差别在 LayerNorm 放置顺序和相应训练动态。现代模型还可能采用 RMSNorm、SwiGLU、不同位置机制或并行残差等变体，不能只凭"有注意力和 FFN"就推断出一张完全相同的计算图。

层与层之间发生什么

假设 X 是 (B=2,n=5,d=512)，一层结束后仍是 (2,5,512)。五个位置的向量已被上下文更新；下一层继续拿这些更新后的表示构造新的 Q/K/V。也就是说，第 2 层看到的不是原始词嵌入，而是第 1 层处理过的状态。位置宽度固定不代表信息不变：每层的投影、混合权重、激活和归一化都可以改变表示。

7.6 ReLU 是教材起点，不是所有模型的配置

原始 Transformer 使用 ReLU FFN，且 dff=4dmodel 是一个经典设置。现代模型也常用 GELU 或门控激活 SwiGLU：典型门控形式将两条升维分支逐元素相乘，其中一条经过 SiLU 等激活，再由下投影回到残差宽度。门控 FFN 的矩阵数与中间宽度设置不同，所以不能把所有模型的 FFN 参数比例都背成 2/3。对入门者最重要的结构事实仍是：FFN 对每个位置使用相同参数，内部做非线性变换，不在这一步混合不同 token。

① 输出行跟着输入排列一起重排（置换等变），没有位置线索就难以分清语序。② Jacobian 中的恒等项提供一条直接梯度路径，可缓解深层优化困难，但不保证梯度绝不消失或爆炸。③ LayerNorm 对每个 token 的特征维独立统计；BatchNorm 通常按通道汇总 batch 样本，依赖 batch 统计。④ 4× 是常见经验设置，不是定律；采用门控激活时常会重新选择中间宽度。

本章常见问题 FAQ · 位置、残差与归一化

RoPE 到底把什么旋转了？它为什么能表达相对位置？

RoPE 通常把每个注意力头的 Q、K 特征按二维一对一组，在位置 m 按预定角频率旋转；Value 通常不做这一步。对某一频率的一对坐标，位置 m 的旋转矩阵记作 Rm，则 q 在 m、k 在 n 时的点积可改写为 qᵀRmᵀRnk=qᵀRn−mk。两侧绝对位置的旋转在点积里合成了相对位移 n−m，因此注意力分数能利用距离线索。它不是把“相对距离”直接写进 Value，也不保证超出训练长度仍可靠；频率缩放、训练长度与具体实现都会影响长上下文表现。

既然 Pre-LN 的梯度路更直接，为什么还要研究 Post-LN？Pre-LN 一定更好吗？

Post-LN 的一个子层写作 LN(x+F(x))，原始 Transformer 使用这种顺序；Pre-LN 写作 x+F(LN(x))，恒等残差支路更直接，许多深层训练设置下较容易优化。两者改变了子层看到的输入尺度与层间梯度路径，因此训练稳定性、表示尺度和最终质量会随深度、初始化、学习率、归一化及训练配方而变。Pre-LN 不是免调参保证，Post-LN 也不是错误架构；比较时需用对应的优化配方和实际任务评估，不能只从一个局部公式断言胜负。

LayerNorm 会跨句子或跨 token 计算均值吗？它和 RMSNorm 有什么区别？

标准 LayerNorm 对每个样本的每个 token，沿该 token 的隐藏特征维计算均值与方差；它不把同批其他句子或其他位置拿来做批次统计。之后用可学习的逐通道 γ、β 缩放和平移。RMSNorm 通常省去减均值这一步，按向量均方根做尺度归一化并学习增益，计算更简洁；两者都规范特征尺度，但计算公式与可表达的变换不同。实际代码还要核对归一化轴、ε 和是否有偏置，不能只凭类名推断完全相同的数值行为。

残差加法会把原输入完整保留下来吗？为什么不直接拼接？

加法确实沿一条恒等支路把 x 直接送到加法节点，给信息和梯度提供短路径；但结果 x+F(x) 中两支在每个通道上相加，后续网络通常无法把它们当成两份独立副本拆开，所以不能说语义信息“完整原封不动”地保存在可读位置。拼接则把通道数扩大为两倍，之后通常需要投影回主干宽度，会改变参数量、计算与形状。标准 Transformer 选择加法，是用固定宽度和直接残差路径换取简洁高效；前提是 F(x) 输出形状能与 x 对齐。

8.2 编码器侧：源句的自我消化

输入："我 / 爱 / 学习" → 嵌入 + 位置编码

为演算形状，假设分词器恰好将源句切成 3 个 token。每个 token id 查出 512 维嵌入，与相同位置的编码逐元素相加，得到 (3, 512)。真实分词器可能把同一汉字词切成不同数量的 token，实际 n 由分词结果决定。

第 1 层自注意力：示意中的早期关系

每个位置都可读取整句。某个学到的注意力头可能把"我"与"爱"或"学习"的上下文联系起来；这只是帮助理解信息交换的示意，真实注意力模式由训练得到，不会预先分配固定的主谓宾角色。输出仍是 (3, 512)，各向量已融合上下文。

FFN：逐词深加工

每个位置独立过 512→2048→512 的非线性网络。形状不变，内涵加深。残差+LayerNorm 保持训练稳定。

① 掩码自注意力："I love" 前缀内部互相看

因果掩码令位置 i 只能看见 ≤i 的位置。实现中常把未来位置的分数加上 −∞（或足够大的负数），再做 Softmax，使其权重为 0。训练时整条目标序列可并行送入，但位置 i 的状态看不到未来答案；这既防止泄漏，又不妨碍批量计算。

Linear + Softmax：落到词表上

最后位置的 512 维状态经词表投影得到约 5 万个 logits；Softmax 把它们转成下一 token 的条件概率分布。若这个示意分布中 "learning" 概率最高，贪心解码才会选它；真实模型输出要由真实参数与输入计算，词表 token 也未必恰好对应完整单词。

关键洞察 · 交叉注意力的方向别记反

记忆口诀：Q 问 K 答，V 送货；谁提问谁出 Q，谁被问谁出 K、V。解码器在提问（"当前译文状态需要源句什么信息？"），所以 Q 出自解码器；编码器的各位置记忆被检索，所以出 K、V。GPT 这类纯解码器语言模型没有编码器交叉注意力层，因为其标准架构没有单独的源序列编码器；它在自身前缀上用因果自注意力。提示词仍然作为前缀参与这条注意力路径。

8.5 翻译时的训练数据：右移一格，预测下一格

设目标答案经分词后是 [I, love, learning, <eos>]。训练时，解码器输入前面加起始符并右移一格：[<bos>, I, love, learning]；监督标签则是原目标序列。于是四个位置分别学习预测 I、love、learning、<eos>。模型对每个位置都计算词表 logits，并用交叉熵惩罚正确 token 的概率太低。这个"把正确前缀喂给模型，再预测下一个 token"叫教师强制（teacher forcing）。

训练不必逐 token 循环：整条右移后的目标一次输入，因果掩码保证位置 1 看不到 I 之后的 token，位置 2 看不到 love 之后的 token，以此类推。编码器输入可以双向查看源句，解码器交叉注意力也可以访问整份源句表示 H，因为翻译时源句已经完整给出；只有目标侧必须遵守从左向右生成的约束。

位置 t解码器输入该位置预测标签因果自注意力可见目标前缀

3lovelearning<bos>, I, love

每个位置最后产生一行 logits zt∈ℝ|V|。Softmax 把正确 token yt 的 logit 转成概率 pt 后，单位置交叉熵是 ℓt=−log pt(yt)；整批训练通常对有效目标位置求和或取平均，padding 标签要从损失里排除。举例说，如果模型给正确 token 0.62 概率，损失约 −ln(0.62)=0.478 nats；只给 0.05 时约为 2.996 nats，惩罚更大。最小化这个数会同时训练词表投影、注意力投影、嵌入及前面所有层，而不是单独训练最后一个 Softmax。

对照表能排除一个常见错位：输入的第 t 项是目标序列中较早的一项，标签却是下一项。例如第 3 行喂入 love，监督的是 learning。若把未经右移的完整答案直接喂进因果解码器，并让当前位置预测同一位置 token，模型可能复制当前 token，而没有完成“从前缀预测后续”的任务；右移目标与因果掩码要一起设计。

实际训练会把多个样本打包成 batch，并对 padding 位置做掩码；词表投影常与输入嵌入共享权重，但不是每种实现都必须如此。这里的 3 个中文 token、4 个英文目标 token 只为演示长度关系，真实 tokenizer 的切分、起止符定义和损失掩码都以具体模型为准。

图中上半部的训练输入来自标签序列右移版本，例如正确标签串是 [I, love, learning, <eos>]，模型一次收到 [<bos>, I, love, learning]。因果掩码令四个位置的计算图彼此遵守前缀限制，所以可以使用矩阵乘法并行计算；每个位置仍只预测其右侧标签。下半部则没有 teacher token 可喂：若模型第一步选择了 We，之后处理的是 [<bos>, We]，而不是表里示意的 I 路线。推理路径会因采样结果改变，这就是训练与推理差异的一部分。

8.6 逐张量审计一次交叉注意力

继续设 batch B=1、源长 n=3、目标输入长 m=4、隐藏宽 d=512、头数 h=8、每头宽 dh=64。编码器最终记忆 H 是 (1,3,512)。目标输入嵌入进入解码器后，每层的掩码自注意力产生 Q/K/V，拆头后各是 (1,8,4,64)，权重矩阵是 (1,8,4,4)，输出重新合并为 (1,4,512)。

接着，交叉注意力的 Query 由当前解码器隐藏状态投影，形状为 (1,8,4,64)；Key 与 Value 都由 H 投影，形状为 (1,8,3,64)。所以 QKT 得到 (1,8,4,3)：四个目标位置分别对三个源位置打分。每行沿源位置轴 Softmax，乘以 V 后得到 (1,8,4,64)，拼头并经输出投影回到 (1,4,512)。注意力不会把 3 个源位置强行压成单个固定向量；每个目标位置都能查询自己的源侧加权混合。

经过各层与最终归一化后，词表线性层把 (1,4,512) 映成 (1,4,|V|) logits。训练时四行都可参与下一个 token 的损失；推理时，当前前缀最后一个位置的 logits 对应"前缀之后该接什么"，根据解码策略选出一个 token，再加入前缀重复计算，直到生成结束符或达到长度限制。

阅读形状时的轴顺序

本讲义用 (B,位置数,特征数) 描述隐藏状态，用 (B,头数,Query位置,Key位置) 描述注意力权重。某些框架内部会把头轴与 batch 合并，或把头维放在另一位置；轴名比死记一个库的打印顺序更重要。

8.7 推理时怎样一步步生成

翻译推理先只输入 <bos>，模型从其末位置得到第一个英文 token 的分布，按贪心、采样或束搜索等策略选一个结果；之后把所选 token 追加到前缀，再预测下一枚。若依次选到 I、love、learning、<eos>，生成就停止。模型给的是条件分布，解码策略才决定怎样从分布得到输出；贪心选择概率最大项不等于全句概率最大的序列，也不保证答案正确。

表内概率是演示用的示意值，重点是条件关系：第 t 步分布依赖源句和已生成前缀，下一步的分布又依赖刚选出的 token。采样会按概率随机抽取；温度可先缩放 logits 再归一化，Top-k/Top-p 会裁掉部分候选；束搜索会同时保留若干前缀。这些策略改变“从分布选 token”的过程，不改变模型输出 logits 的基本定义。贪心每步取最大值可能错过累计概率更高的完整序列。

朴素实现每一步都会重算整段前缀的注意力。常见 KV cache 会保存先前 token 的 Key 和 Value，新增 token 时只计算它的新 Q/K/V 与历史缓存的交互；编码器的 H 也只需编码一次，交叉注意力的 K/V 可缓存供每一步复用。缓存能减少重复运算，但其显存随批量、层数、序列长度和 KV 宽度增长，这正是 GQA/MQA 等结构关注的工程原因之一。

例如有 L 层、batch B、缓存长度 T、每层 hkv 个 KV 头、每头宽 dh，仅保存 K 与 V 的元素数约为 2LBThkvdh，再乘每个元素的字节数就是粗略显存需求，尚未计入临时缓冲与对齐开销。标准多头注意力的 hkv 通常等于查询头数；GQA/MQA 让多个 Q 头共享较少 KV 头，从而压低缓存占用。长度 T 增长时缓存近似线性增长；它节省重复计算，但不是“免费记忆”。

不要把训练与推理的顺序混成一件事：训练有标准答案，可并行计算所有目标位置并用掩码挡住未来；推理没有未来答案，模型必须等本步 token 选定后才能继续。两者使用同一套参数与因果规则，却有不同的数据流和计算效率。

本章常见问题 FAQ · Seq2Seq 的信息怎样走完全程

交叉注意力是不是一张“源词—目标词对齐表”？

它会产生目标位置对源位置的权重矩阵，所以常被画成类似对齐热图；但这只是每层每头的读取份额，不保证每个目标词对应唯一源词。一个目标位置可以混合多个源位置，同一个源位置也可被多个目标位置读取；短语重排、子词切分、上下文补全更不会总是一对一。真正的输出还经过 Value 混合、头间组合、残差、FFN 与后续层。若要声称某格是可靠词对齐，需要专门定义对齐任务并验证，不能仅凭交叉注意力图下结论。

交叉注意力里目标能读完整源句，会不会因此偷看未来？

标准翻译任务在生成目标句之前，完整源句已经给定；所以解码器的每个目标位置都可以读取全部有效源位置，源句方向通常不加因果掩码。必须遮未来的是目标侧自注意力，因为目标 token 尚未生成。若源 batch 有 padding，交叉注意力仍要屏蔽源侧 PAD Key；若任务本身是流式翻译、语音同步或其他“源信息也逐步到达”的场景，则还需额外限制可见源前缀，不能直接照搬离线翻译的全源可见假设。

为什么交叉注意力权重是 m×n？它怎样把不同长度的两句话接起来？

设源句经过编码得到 H:(B,n,d)，目标当前状态是 D:(B,m,d)。交叉注意力从 D 投影出 Q:(B,h,m,dh)，从 H 投影出 K、V:(B,h,n,dh)；于是 QKᵀ 是 (B,h,m,n)，每个目标 Query 对 n 个源 Key 分配一行权重，乘 V 后回到 (B,h,m,dh)，拼头并投影后得到 (B,m,d)。源长 n 与目标长 m 无须相同：每个目标位置都形成自己的源信息混合，而非先把源句压成一个固定向量。

推理时为什么编码器只跑一次，交叉注意力的 K/V 也能缓存？

源句在整段生成期间不变，所以编码器输出 H 只需计算一次。对每个解码器层，H 经该层固定的 K/V 投影得到源侧 K、V；它们之后每个生成步都相同，可以缓存复用。目标前缀则每步增加一个新 token：实现可用 KV cache 保存已有目标自注意力 K/V，只算新位置，并让新 Query 读取历史缓存；交叉注意力只需用新目标 Query 读取已缓存的源 K/V。缓存降低重复投影和计算，却会占随源长、目标长、层数、batch 与 KV 头宽增长的内存。

教师强制训练每一步都喂正确答案，为什么推理时还可能越走越偏？

训练时位置 t 通常看到数据集给定的正确前缀，再用交叉熵学习预测下一 token；推理时模型必须把自己刚选出的 token 接到前缀。若早期选择与参考序列不同，后续上下文也随之改变，模型就可能进入训练中较少见的前缀，这类训练—推理分布差异常称 exposure bias。它不表示教师强制本身无效：它能并行提供清晰的逐位置监督；但序列质量还受采样/搜索策略、数据、模型置信度与错误恢复能力影响。推理时生成不是把训练时整句标签再喂一次。

训练：老师强制、掩码与交叉熵的协奏

推理时模型逐词生成，训练时却能一步到位算出所有位置的损失——这个"作弊又不作弊"的技巧是本章主角。我们从一个可手算的预测任务出发，走完数据右移、因果掩码、损失、梯度和优化器更新，再看为什么同一个模型到了线上必须一步一步写字。

9.1 训练目标：永远是同一个问题

对 GPT 这类纯解码器，经典预训练目标是自监督的下一个 token 预测：拿文本本身作为输入和答案，无需人工逐词标注。编码器—解码器翻译任务则通常使用平行语料（源语言句子和人工译文），属于有监督条件生成；若做去噪预训练，也可以构造自监督目标。两类模型的条件概率都能分解为逐位置预测，但不能因此把所有训练数据和目标都叫作同一种自监督。

损失函数用交叉熵（Cross-Entropy）：模型对正确词给出的概率越高，损失越小。若正确词是 "learning"，模型给它 0.9，损失 = −log(0.9) ≈ 0.105；若只给 0.01，损失 = 4.6——惩罚会随错误概率降低而按负对数增大，逼模型认真对待每个词。

把「概率」翻译成一个可手算的例子。假设当前位置词表只有 {I, you, learn}，模型输出 logits [2.0, 0.5, −0.5]，正确标签是 I。Softmax 给出大约 [0.766, 0.171, 0.063]，所以这一步的交叉熵是 −ln(0.766)≈0.267。若正确标签其实是 learn，同一组 logits 的损失就是 −ln(0.063)≈2.77。交叉熵只读取目标类别的 log 概率；其他类别虽没有单独的目标项，却通过 Softmax 的归一化分母影响目标概率，因此梯度会同时把正确类往上推、把竞争类相对压低。

数值实现一般直接用 torch.nn.functional.cross_entropy(logits, target)，不要先手写 Softmax 再把概率送进去：这个函数把 log_softmax 与负对数似然合在一起，用 log-sum-exp 技巧避免概率极小时下溢。对单个位置，若正确类 logit 是 zᵧ，损失可写成 −zᵧ + log Σⱼ exp(zⱼ)。因此，一个很大的正确 logit 仍可能有不小损失，关键是它相对于竞争 logits 是否足够大。

工程报告中常看到的是它的指数形式 困惑度（Perplexity, PPL）= e^L（当平均交叉熵以自然对数计算时）。常用直觉是「模型每一步的平均不确定性」，但不是说词表里真的只剩 PPL 个候选。一个例子：三步预测正确 token 的概率分别为 1/2、1/4、1/8，平均损失为 (ln 2 + ln 4 + ln 8)/3 = ln 4，所以 PPL=4。它会受分词器、语料领域、是否计入特殊 token 影响；跨 tokenizer 的数值通常不能直接排队比较。

报告 PPL 时至少要交代评估语料、tokenizer、是否加入 BOS/EOS、哪些标签计入平均，以及模型是否可能见过同一文档或近重复内容。若一批里有不同长度的句子，常见的 token 平均是把所有有效 token 损失相加后除以有效 token 数；「先对每句求平均再平均句子」会让短句和长句拥有相同权重，是另一项指标。不同论文若口径不同，哪怕都写 PPL，也不一定可直接比较。

把目标写完整

对一批序列，令源输入为 x，目标 token 为 y₁…yₘ。模型按链式法则分解联合概率：P(y₁…yₘ | x) = ∏ₜ P(yₜ | y₍ₜ₋₁₎…y₁, x)。最大似然训练就是让真实译文在这条分解路径上的概率乘积尽量大；数值实现取负对数，把乘积变成逐 token 损失之和。PAD 位置与无效标签必须从分子、分母中一起排除。

9.2 Teacher Forcing：考试时看着答案学，但试卷不泄题

朴素想法：让模型像推理时那样自产自销地训练——慢且错上加错（前面错后面全崩）。实际做法是 Teacher Forcing：把标准答案的前缀直接喂给解码器，让模型在每个位置都预测下一个词：

teacher forcing 示意目标译文:  I   love   learning
解码器输入: [BOS] I     love          ← 右移一位，喂"标准前缀"
预测目标:    I     love  learning     ← 每个位置预测"下一个"
一次前向 = 3 个位置的损失同时算出，全程并行！

但这里有个致命隐患：位置 3 预测 "learning" 时，输入里明明有 "love"——如果模型能"往后看"，它可以直接抄袭答案，训练信号作废。闸门就是因果掩码（causal mask）：

关键洞察 · 训练与推理的"错位统一"

训练：答案右移一格当输入，一次前向算出全序列损失（快）。推理：没有答案，只能逐词生成、把输出接回输入（慢）。掩码保证两者可见的位置范围一致——第 i 个位置只读取前缀与当前位置；但内容来源不同：训练前缀来自真值，推理前缀来自模型生成，错误也可能逐步累积。这个“范围一致、输入分布有差异”的区分是理解暴露偏差的关键。

沿着一条样本逐位置核对

假设目标 token 编号是 [I, love, learn, EOS]，解码器输入就构造为 [BOS, I, love, learn]，标签是前一行整体右移后的目标。输入位置 0 的 logits 监督 I，位置 1 监督 love，位置 2 监督 learn，位置 3 监督 EOS。批量张量通常是：输入 decoder_ids: (B,T)，输出 logits: (B,T,V)，标签 labels: (B,T)。损失先把前两维展平为 (B·T,V) 和 (B·T)，但统计平均时只除以非 PAD 标签数。注意标签可以由数据管线直接准备；模型本身不需要逐步调用四次。

在编码器—解码器模型里还有两种掩码，不要混为一谈：编码器 self-attention 通常用 padding mask 忽略源句补位；解码器 self-attention 用 padding mask 加 causal mask，既看不到补位，也看不到未来目标；交叉注意力用源端 padding mask，但不对源句做因果遮挡，因为整句源文在翻译开始前已经可见。mask 的逻辑取决于「query 在问什么、key 属于哪段序列、该序列哪些位置在此时可用」，不能见到一个 mask 张量就默认它是上三角。

容易漏掉的边界是 EOS 与 PAD：EOS 是有效目标，模型通常需要学会何时结束；PAD 只是凑齐批次长度的占位符，不该被当成可预测答案。对 decoder-only 的定长连续文本块，标签常直接右移一格；最后一个真实 token 的后继可能是 EOS，也可能是下一个块里的 token（取决于切块策略）。若多个文档被拼接，必须明确文档边界和跨文档上下文策略；只屏蔽 PAD 不能自动阻断文档间信息。

热身段的学习率随步数线性增加，达到峰值后按步数平方根衰减。直觉上，随机初始化的网络刚开始还没有稳定表示，先小步更新能避免注意力 logits 和残差支路剧烈摆动；训练后期则用更小步长细化参数。今天常见的大模型配方会选 AdamW、warmup 加 cosine decay、权重衰减与梯度裁剪等组合，但具体数值要随模型规模、批次 token 数、数据质量和精度格式调试，不能把一组超参当作普适定律。

把调度式两段拆开看：当 s<w 时，min(...)=s·w⁻³ᐟ²，所以学习率按训练步数线性增加；当 s>w 时，较小项变成 s⁻¹ᐟ²，学习率以步数平方根的倒数缓慢衰减。峰值约为 d_model⁻¹ᐟ²·w⁻¹ᐟ²，因此模型宽度和 warmup 长度共同决定峰值。原论文的具体数值属于其优化配方的一部分；现代复现最好报告峰值学习率、warmup 步数、总训练 token、batch token 数与衰减曲线，单报「用了 Adam」不足以复现实验。

每一步也不等于每个样本独立更新。通常先累积一个批次的 token 损失，反向传播得到批次梯度，再由 Adam 的一阶、二阶动量估计更新权重。若使用梯度累积，连续几个微批次的梯度先相加或取平均，达到目标有效批量后才更新一次；若采用数据并行，多张卡还要同步或规约梯度。务必记录的是实际参与训练的 token 数与更新步数，而不是只记录 epoch，因为大语料往往没有传统意义上的「完整扫完一遍」。

重复许多更新步

每步抽取新的 token 批次，训练集之外还要定期在验证集算损失。停止标准由 token 预算、验证指标与算力决定，不是固定的「几亿次」；数据、去重与采样比例会直接改变模型学到什么。

Adam 的更新可以粗略读作「先平滑梯度，再按近期梯度平方的尺度归一化」：mₜ = β₁mₜ₋₁ + (1−β₁)gₜ，vₜ = β₂vₜ₋₁ + (1−β₂)gₜ²；初始化为零会让动量估计早期偏小，因此再做 m̂ₜ=mₜ/(1−β₁ᵗ)、v̂ₜ=vₜ/(1−β₂ᵗ) 的偏差修正，参数按 θₜ=θₜ₋₁−lr·m̂ₜ/(√v̂ₜ+ε) 更新。它并不会知道英语语法或程序结构；它只根据梯度调整参数，让训练目标下降。AdamW 把权重衰减从梯度动量通路中解耦，和直接对损失加 L2 惩罚并不完全相同。训练时的 dropout 通常打开，验证/生成时切换到 eval()，否则随机失活会让验证结果带噪声。

反向传播怎样把「learning 的概率太低」变成参数更新？对 softmax 加交叉熵而言，单个位置的 logit 梯度有一个很好用的简式：∂L/∂zⱼ = pⱼ − 1[j=y]。目标类别的梯度为负，会鼓励优化器提高它的 logit；其他类别的梯度为正，会相对压低它们。梯度先传到输出矩阵和最终隐藏状态，再穿过每个 block 的 FFN、注意力、残差和归一化，最终抵达词嵌入与位置参数。一个参数会参与许多 token、许多样本的计算，因此批次反向会把这些局部误差累积成一个更新方向。

若一个训练步累计了 N 个有效目标 token，token 平均损失通常是 Σᵢℓᵢ/N；若不除以 N，梯度尺度会随批次 token 数变化。多卡训练若每张卡先算各自均值再简单平均，而各卡有效 token 数不同，等于让每张卡权重相同、而不是让每个 token 权重相同。严格的全局 token 平均要按有效 token 数加权规约，或者先规约 loss 总和与计数再相除。大量 PAD、变长批次或最后一个不完整批次时尤其要留意。

9.5 常见问题 FAQ：把训练目标和掩码对齐

Q1：右移一格之后，序列最后一个 token 的目标去哪了？

把「输入」和「标签」看成同一条 token 流的两段错位视图：若完整样本是 [BOS, 我, 爱, 学习, EOS]，训练输入可为 [BOS, 我, 爱, 学习]，标签为 [我, 爱, 学习, EOS]。这样每个输入位置都有一个“下一个 token”目标，EOS 也能被学到。若语料没有显式 BOS/EOS，通常直接从连续文本流构造输入与向前错一位的标签。

定长切块时要先决定边界语义。想让模型在块末预测下一个真实 token，数据管线要为每个长度为 T 的输入多取一个后继 token；若每块只有恰好 T 个 token，再在块内切成 T−1 对，则每块末尾自然没有标签。把文档独立训练时可在边界加入 EOS；把文档拼成连续流时则要明确是否允许跨文档上下文。关键不是某种切块法唯一正确，而是不能无意间丢掉边界目标或把不该相连的文本接起来。

Q2：padding mask 和 loss 中的 ignore index 是不是同一个掩码？

不是。Attention mask 决定一个 query 可以读取哪些 key；loss mask（例如 ignore_index）决定哪些位置的标签进入损失与梯度。只忽略 PAD 标签，不会自动阻止别的位置把 PAD 当作注意力上下文；只屏蔽 PAD key，也不会自动让 PAD 标签从平均损失的分母中消失。它们经常由同一个长度张量派生，但作用在不同计算阶段，必须分别核对。

补充一个容易忽略的细节：右侧补齐、纯因果解码时，真实 token 的 query 本来就看不到它右边的 PAD key；不过 PAD query 的输出仍应从损失中排除。双向编码器、交叉注意力，或左侧补齐、打包样本等布局则可能让有效 query 看见 PAD，因此需要正确的 key padding mask。无论哪种布局，都不能把某个有效 query 的所有 key 全部屏蔽，否则对全 −∞ 行做 Softmax 会产生 NaN。

Q3：不同模型的 PPL 数字可以直接比较吗？

只有评估口径足够一致时，PPL 才适合直接对照。至少要统一原始语料、文档边界、上下文截断与滑窗策略、哪些 token 计入损失，以及是否把 BOS/EOS 等特殊 token 算进去；评估还应避免训练集泄漏。标准 token PPL 是有效目标 token 的平均负对数似然取指数，所以分母必须是实际计分的 token 数，而不是句子数或包含 PAD 的张量长度。

跨 tokenizer 时尤其不能把 PPL 当成绝对排行榜：同一句文本可能被切成不同数量、不同难度的 token，tokenizer 的词表和规范化规则也会改变每一步的预测问题。若要比较不同分词器，可考虑统一原始文本单位上的 bits-per-byte 等指标，并确认文本编码和特殊 token 的处理可比。即便口径一致，低 PPL 也只说明模型更善于给这份分布中的下一个 token 分配概率，不直接证明事实正确、指令遵循更好或长文推理更强。

Q4：为什么 PyTorch 的交叉熵直接接 logits，不能先 Softmax 再传？

F.cross_entropy(logits, target) 内部已经稳定地执行 log_softmax 与负对数似然。它利用 log-sum-exp 计算，避免先把极小概率显式变成浮点数、再取对数时发生下溢。若先 Softmax 再送入该函数，函数会把概率数值误当成新的 logits 再做一次 Softmax；所得目标和梯度都不是原先想优化的交叉熵。

形状也要配套：类别轴必须对应词表，目标张量保存目标类别的整数 ID。比如 logits: (B,T,V) 可展平为 (B·T,V)，标签同步展平为 (B·T,)；对 PAD 的忽略策略仍要确保只对有效 token 计平均。验证 PPL 时若训练用了 label smoothing，应用未平滑的真实标签负对数似然另行计分，否则指数化的平滑训练目标不是标准 PPL。

推理：一个词一个词地生成，以及怎么选词

10.1 自回归循环：输出的尾巴接回输入

Step 0 · 编码器只跑一次

Step 1 · 解码器输入 [BOS]

前向 → 最后位置 logits → Softmax → 选 "I"。接回输入。

Step 2 · 输入 [BOS, I]

再前向 → 选 "love"。

Step 3 · 输入 [BOS, I, love]

→ 选 "learning"。

Step 4 · 输出 [EOS]，停机

译文 "I love learning" 完成。每个词都凝固后再写下个词——不可撤销，错误会滚雪球。

这段故事里，编码器—解码器翻译模型和 GPT 需要稍作区分。翻译模型先把源文整句编码成 H: (B,S,d)，解码器每步用当前译文前缀做因果 self-attention，再以查询 Q 去交叉注意力读取固定的源文 K,V。GPT 类纯解码器没有单独的源文编码塔；提示词和已生成内容一起成为同一条因果序列的前缀。两者都按目标 token 自回归生成，但缓存的状态组成不同：前者除各层 decoder self-attention 的 KV 外，还可缓存源端 cross-attention 的 K/V；后者只需缓存生成序列各层的 K/V。

单步生成可写成这个逻辑骨架。sample_or_select 代表 greedy、采样或 beam search；模型算出的 logits 不是已经选定的词，而是词表中每个 token 的未归一化分数。

生成循环的简化伪代码tokens = [BOS]
对 step = 1 … max_new_tokens:
    logits = model(tokens) 的最后一个位置
    next_id = sample_or_select(logits)
    tokens.append(next_id)
    若 next_id == EOS：停止

实际系统会避免每一步都把整个 tokens 从头送入模型：首次把提示词整体并行处理，之后仅送入新 token，并把旧状态从 KV cache 读取。这不会让 token 之间变成并行生成；它只让旧前缀不再重复投影与计算。批量解码多个请求时，每条序列长度可能不同，因此还要处理 padding、连续批处理（continuous batching）、请求取消与缓存块分配。

为什么推理慢？——KV Cache 登场

因果掩码保证过去位置的表示不依赖未来，所以前缀中每层已经算出的 Key、Value 可以留给后续步骤重复使用。没有缓存时，第 t 个 token 到来后重新跑长度 t 的前缀，注意力要处理此前所有位置；有缓存时，只为新 token 计算 Q/K/V，并让这个 Query 读取长度约 t 的缓存。对单个新 token，每层注意力计算从重算前缀的近似 O(t²d) 降为 O(td)；不过生成 T 个 token 的总注意力工作量依旧随上下文长度二次增长，KV cache 不是把整个长序列生成改成线性复杂度。

缓存显存可粗估为 2 × 层数 × 批量 × 序列长度 × KV 头数 × 每头维度 × 每元素字节数，系数 2 来自 K 和 V。例：32 层、batch=1、上下文 8192、8 个 KV 头、每头 128 维、BF16 每元素 2 字节，缓存约 1 GiB；若有 64 个 KV 头，则约 8 GiB。实际实现会受张量布局、对齐、分页与临时缓冲影响。GQA/MQA 让 KV 头数小于 Query 头数，直接按比例缩小缓存；代价是 KV 投影表示能力的设计折衷。权重、KV 与临时工作区都占显存，具体谁先成为瓶颈取决于模型、并发数和上下文长度。

这里的「每个位置表示不依赖未来」有严格前提：模型使用因果 self-attention，参数在推理过程中保持不变，旧 token 的位置编号/位置编码也没有被重排。加入新 token 不会改变旧 token 在较早层已经得到的隐藏状态，因此旧层内 K/V 可复用。若你改写提示词、删除中间 token、改变左侧上下文或模型权重，后缀位置的缓存就不再对应新的计算图，必须失效或重新计算。Cross-attention 的 encoder K/V 则源于固定源文，翻译解码期间通常整段复用。

KV cache 的显存随并发请求线性叠加。把单请求上下文翻倍，KV 缓存近似也翻倍；把并发 batch 从 1 提到 16，若每条请求长度相同，缓存量也约乘 16。动态批处理为了容纳不同长度的请求会面对碎片和分配问题，分页缓存把 K/V 切成定长块、按需分配，并允许请求结束后回收块。它改善内存管理，不会让单个请求的注意力突然不再读取它的历史。

10.2 解码策略：同一个模型，百种文风

Softmax 给出的是一整张概率分布表，"选哪个词"本身就是一门学问：

策略做法性格
贪心 Greedy每步选 argmax确定、保守；局部最大不保证整句联合概率最大，易陷入重复
束搜索 Beam Search每步保留最多 k 条当前评分较高的部分序列，最终按设定分数选一条常用于机器翻译；有限束宽会剪枝，不保证找到全局最高分序列；对话里常显呆板
温度采样logits ÷ T 再采样T<1 更保守，T>1 更狂野
Top-k只在概率最高的 k 个词里采样砍掉长尾，防止抽到离谱词
Top-p（核采样）只在累计概率达 p 的最小集合里采样自适应：分布尖则候选少，平则候选多

这些策略要从「局部选词」与「整段评分」的差异来理解。贪心每一步只看眼前最大条件概率 token，完全不考虑这个选择会怎样改变后续分布。由于一个次优的当前词可能开启一条高概率后缀路径，贪心不保证找到模型定义下联合概率最高的完整序列。束搜索则每步保留 K 条部分序列，累计每步 log-probability，并按设定评分扩展和剪枝；有限的束宽通常只能近似搜索，不能保证找到整个序列空间中的全局最高分结果。它常搭配长度惩罚，因为直接相加的 log 概率总是非正数，长句自然更吃亏。束宽增大只是在更充分地搜索模型偏好的序列，并不保证更真实、更有帮助，甚至可能放大模型的高频套话。

Top-k 先按概率保留 k 个 token，再在这个子集上重新归一化采样；Top-p 则从最高概率开始累加，到总和首次达到阈值 p 时停止保留，候选集合大小会随分布形状变化。两种截断都必须明确排序、阈值边界与重归一化规则。实践里常先做温度缩放，再做 top-k/top-p 筛选；重复惩罚、禁用 token 或最小生成长度也会修改 logits。筛选顺序会改变结果，比较系统时不能只报一个「temperature=0.8」。

例如原分布是 [0.50, 0.25, 0.15, 0.10]，Top-p 取 p=0.8 时保留前三项（累计到 0.90，集合内再归一化），而 Top-k 取 k=2 固定只留前两项；若分布很平，Top-p 往往纳入更多候选，Top-k 的候选数量始终固定。温度缩放后才筛选时，累计概率也要用温度后的分布重新计算。采样是随机操作；想复现实验还需记录随机种子、模型版本、prompt、截断规则和停止条件。

关键洞察 · 训练追求准确，生成讲究分寸

训练目标（极大似然）只教模型"什么词合理"，从不教"该多大胆"。贪心解码在数学上最忠实于训练目标，在体验上却最无聊——开放生成需要刻意注入随机性。这就是为什么同一个模型既能写严谨的代码注释，也能写天马行空的小说：变的只是解码参数。

10.3 推理阶段的工程全景

  • Prefill 与 Decode 两阶段：整段输入提示称为 prefill，可并行计算各位置并建立 KV cache；之后逐 token 生成称为 decode。Prefill 常有较大的矩阵乘法、吞吐更看算力；Decode 每步只计算少量新 token，却要读取模型权重和越来越长的 KV cache，常受显存带宽或缓存容量限制。硬件、批量和上下文长度会改变瓶颈，不能把「Prefill 算力受限、Decode 带宽受限」当作无条件定律。
  • 停止条件：生成 [EOS]、达到长度上限、或命中停用词表。
  • 重复惩罚：对已出现 token 的 logits 施加频率惩罚或乘法惩罚，能缓解循环复读，也可能伤害代码、固定术语和有意重复的文体；它是解码启发式，不会改变模型权重。
  • 投机解码（Speculative Decoding）：草稿模型先提出一小段候选 token，目标模型可利用因果并行性一次核验这些候选。精确采样算法需按草稿分布与目标分布执行接受/拒绝和修正重采样，才能保持目标分布不变；仅仅「批量验证并在第一个不匹配处截断」一般不自动保证分布完全一致。加速幅度取决于草稿命中率、两模型速度差和批量。

推理服务还要在延迟与吞吐之间做调度。一次只服务一个请求最容易理解，却会让 GPU 等待；把多个请求组成批次通常提高吞吐，但慢请求可能拖住短请求。连续批处理允许新请求在旧请求生成期间进入空出的槽位；PagedAttention 一类设计把 KV cache 按块管理，减少变长请求造成的显存碎片。量化权重可以减少模型权重的显存与带宽占用，但数值误差可能影响质量；KV 量化则针对缓存另做近似。它们都是推理系统优化，和「模型如何选择下一个 token」属于不同层次。

10.4 常见问题 FAQ：把采样、搜索与缓存分清

Q1：Top-p 和温度同时使用时，先后顺序会影响结果吗？

会。常见流程是先将 logits 除以正温度 T，再做 Softmax 得到新分布，按这个分布由高到低累计并选出达到阈值 p 的最小候选集合，最后在保留集合内重新归一化采样。温度会改变概率的尖锐程度，因此可能改变 Top-p 边界上的候选集合；如果先截断再改温度，得到的就不是同一套候选和概率。

例如原概率为 [0.50, 0.25, 0.15, 0.10]，p=0.8 会保留前三项，因为累计概率要到第三项才首次达到阈值。温度变化后必须重新计算累计值。Top-p 的 p 是过滤前分布上的累计质量阈值，不是“最终抽样命中概率保证”；集合内重归一化后，各 token 的实际抽中概率会再次变化。想复现实验，还要记录滤波顺序、随机种子、停止规则和具体实现的边界约定。

Q2：束搜索累计的 log 概率为什么常要再做长度归一化？

一条序列的条件概率是逐 token 条件概率的乘积，取对数后变成各步 log 概率之和；每项通常不大于 0，因此直接累计会让较长候选更容易得到更低的总分。翻译等任务里，短译文可能因此被偏爱，即使它遗漏了源文内容。常见长度惩罚会把累计分数按长度函数归一或修正，让不同长度的候选有机会公平比较。

惩罚不是纯技术补丁：太弱仍偏短，太强会偏长或诱发赘述；束宽只控制每步保留多少条部分路径，有限束搜索也会剪掉最终可能更好的路径。束搜索通常是在模型给定的序列评分上做确定性候选扩展，而采样是在下一个 token 的分布中随机抽取；增加束宽不等于增加创造力，也不保证找到全序列空间的全局最优，更不保证人类偏好最高。

Q3：对话历史被编辑或系统提示改变后，旧 KV cache 还能接着用吗？

只有缓存对应的前缀计算仍完全相同，才可复用。若只是把完全相同的旧前缀向右追加新 token，历史各层的 K/V 仍匹配；若改写或删除中间消息、改变前缀顺序、切换模型权重或位置编号，后续隐藏状态已经对应另一条计算路径，相关缓存必须失效并从最早受影响的位置重新计算。工程里的“前缀缓存”通常以 token IDs、模型/适配器版本、位置与注意力配置等作为匹配条件，而不是仅凭文字看起来相似。

因此，多轮对话若把完整对话模板每次重组，服务端只有在新请求精确共享同一 token 前缀时才能安全复用缓存；只要系统消息、工具结果或模板 token 改了，就不能盲目拼接旧缓存。缓存键必须包含所有影响前向结果的状态；否则复用会造成隐蔽的错答，而非单纯的性能差异。

Q4：KV cache 会占多少显存，怎样知道它是不是服务瓶颈？

对常见 dense KV 布局，单请求缓存字节数可先估为 2 × 层数 × token 数 × KV 头数 × 每头维度 × 每元素字节数；批量为 B 时再乘 B。例如 32 层、8192 个 token、8 个 KV 头、每头 128 维、BF16（2 字节）约需 1 GiB，未计分配对齐、分页元数据、临时工作区等开销。并发数增长时，每条请求的缓存还会叠加。

把估算与实际可容纳的并发、上下文和生成上限一起看：若增长上下文或 batch 后可用显存很快耗尽，KV 就可能限制服务容量；若内存尚充足但每 token 延迟较高，也可能是权重/缓存读取带宽或 kernel 调度瓶颈。GQA/MQA 减少 KV 头数，缓存量化减少每元素字节，分页管理改善变长请求的分配；这些手段针对不同因素，实际收益仍需在目标硬件、并发和上下文分布下测量。

Chapter 11 · 通往现代

现代变体：BERT、GPT、T5 到 LLaMA 的血缘图谱

同一个 Transformer，三种拆法，演化出今天的整个大模型生态。学完本章，新闻里的模型名再也不是黑话。

11.1 三条演化路线：留左、留右、全都要

先记住「编码器/解码器」说的是网络结构，不是模型聪不聪明，也不是它能不能处理文字。原始 Transformer 由两者组成：编码器双向读取输入，解码器用因果自注意力逐步生成，并通过 cross-attention 读取编码器输出。后来研究者发现，针对具体目标保留一边，常能得到更合适的训练接口。

路线注意力可见范围代表预训练目标适合什么
Encoder-only · BERT输入中双向可见（被选中的 token 会被破坏或遮挡）Masked Language Modeling；早期 BERT 另有 NSP句子分类、抽取式问答、语义检索表征

这个图也解释了三类模型的训练接口为什么不同。BERT 的被遮位置可以利用左、右上下文，例如在「今天天气 [MASK] 好」里同时读到左右邻词；GPT 预测第 i 个 token 时，右侧目标根本不可见，因此能自然用于从提示前缀续写；T5 的 decoder 不能偷看未来答案，但 cross-attention 可读取 encoder 已经处理完的整段输入。所谓「双向」指某层允许位置间双向信息流，不代表句子顺序被丢弃：位置嵌入与 token 顺序仍在输入表示中。

BERT 的典型 MLM 训练会从输入中选取约 15% 的 token 作为预测目标；原版策略把这些目标位置中的 80% 换成 [MASK]，10% 换随机 token，10% 保持原 token。注意：三项比例针对的是被挑中的位置，若按全序列计算，被替换成 [MASK] 的位置约占 15%×80%=12%。保留原词与随机替换让模型不能只依靠是否看见字面 [MASK] 判断「这里一定有缺词」，但预训练时大量出现、下游输入中通常不出现的 [MASK] 仍会造成一定预训练/微调差异。模型可同时参考目标左右两侧，因此学到的是「给定上下文填空」，而不是从左向右逐词续写。原版 BERT 还用 NSP 判别两个片段是否相邻；后续 RoBERTa 研究显示，去掉 NSP、调整数据规模和训练设置也能取得更强结果。这比较的是完整配方，不能把差异全归因于一个目标。现代 encoder 模型并不都照搬 BERT 配方。

这让 BERT不是原生的自回归生成器，但说它绝对「不能生成文字」也不准确：可以用迭代填空或另外接生成头来产出文本，只是生成机制、训练分布和 GPT 的逐词采样不同。反过来，GPT 虽能处理问答和分类，也不代表它以双向方式读取提示词；每个目标 token 仍受因果约束。理解模型应用时要同时看架构、预训练目标、微调方式和推理接口，不能只看名字。

T5 把任务统一成文字输入与文字输出，例如输入 translate English to German: That is good.，目标是一段德语译文。其 span corruption 会把输入中的若干连续片段替换成哨兵符号（如 <extra_id_0>），再让 decoder 按顺序生成各个被删片段及后续哨兵标记。若原句被破坏为「The <extra_id_0> sat on the <extra_id_1>.」，目标可组织成「<extra_id_0> cat <extra_id_1> mat <extra_id_2>」。具体跨度抽样和哨兵约定按 T5 配方定义。编码器双向理解保留下来的内容，decoder 则按因果顺序重建目标；这保留 seq2seq 的条件生成接口，但推理时需要先运行 encoder，再运行 decoder。

为什么 decoder-only 后来很流行？单一的 next-token 目标几乎能直接应用到网页、代码、书籍和对话，只要把文本变成 token 流；提示词还能把任务示例、规则和上下文放在统一前缀里。它的代价是生成必须串行，而且模型对输入的双向交互通过提示构造和多层因果网络间接实现。BERT 并没有「输给 GPT」后消失：编码器至今仍适合嵌入与检索；T5 类架构在许多转换任务中也自然。架构选择是目标函数与部署成本的取舍。

11.2 LLaMA 式现代积木：论文版 Transformer 的常见升级

这些是以 LLaMA 一系为例的常见现代选择，不是所有新模型的统一标准。比如有的模型保留 LayerNorm，有的使用不同位置方案或注意力变体；新名词出现也不表示旧方案已经失效。读架构图时要先问：训练目标是什么？每层的张量形状是什么？改动节省了哪种计算/内存，又引入什么约束？

Pre-LN 与 RMSNorm。原始 Transformer 每个子层先做变换、加残差、再 LayerNorm（Post-LN）。深层训练中，Pre-LN 把归一化放在注意力/FFN 前：x ← x + F(Norm(x))，于是残差主路保持近似恒等映射，梯度更容易穿过许多层。RMSNorm 可写作 RMSNorm(x)=g ⊙ x / √(mean(x²)+ε)：只按均方根缩放，不先减均值；它更简单但不是「绝对更好」，选择依赖训练稳定性、实现和模型配方。

SwiGLU。普通 FFN 是 W₂·σ(W₁x)。门控 FFN 可示意为 W₂(SiLU(xW₁) ⊙ xW₃)，两条升维支路一条产生内容、一条产生门控，再逐元素相乘。门控增加参数或计算，因此在对比时应关注参数预算和隐藏维度是否对齐；它的收益来自可学习的逐维开关，不是免费换一个激活函数。

分组查询注意力 GQA。若 Query 头数为 h_q、KV 头数为 h_kv，每组 Query 头共享一组 Key/Value；整齐分组时每组约有 h_q/h_kv 个 Query 头。MHA 对应 h_kv=h_q，MQA 对应 h_kv=1，GQA 处在中间。它主要减少 K/V 投影与缓存体积；每个 Query 头仍有自己的 Q，因此不会按相同比例减少所有注意力计算。是否能保持质量要看具体模型和训练，不应把某个公开架构的经验推广成零损失定律。

看张量就更清楚：若 d_head=128、h_q=32、h_kv=8，Q 的形状是 (B,32,T,128)，K/V 各是 (B,8,T,128)。每四个 Q 头映射到一组 K/V 头做匹配，但最终仍产生 32 个头各自的注意力输出。相较 32 组 MHA，缓存里的 K/V 元素数约为四分之一；Query 投影、注意力权重与输出维度仍取决于 32 个 Query 头。服务吞吐是否按比例提升，还取决于内核是否原生支持 GQA，以及读写带宽、batch、上下文和调度开销。

Tokenizer 词表也属于系统设计。子词算法让罕见词能拆成常见片段，避免词表为每个词形存一行；更大的词表可能缩短多语言或代码 token 序列，却会增大 embedding 与输出头参数，也会影响训练 token 计数、上下文可容纳的字数和跨模型 PPL 可比性。BPE、SentencePiece 是常见工具/算法族，不等于某个固定词表规模。

进阶 · RoPE 一分钟直觉

把 q、k 的每对相邻维度看作二维平面上的向量。位置为 m 的 q 旋转 m·θ，位置为 n 的 k 旋转 n·θ；内积中的旋转差只与 n−m 有关，所以每个频率分量携带相对位移信号。数学上可用复数乘法写成 q·e^(imθ) 与 k·e^(inθ)。这不表示注意力只看距离，也不保证任意长度外推都可靠；旋转频率、训练上下文、模型学到的模式共同决定长程表现。NTK-aware scaling、YaRN 等是不同的扩展策略，需要长上下文训练或评测校验，不能把它们概括为「调一个底数即可无损外推」。

进阶 · GQA：显存与效果的折中

MHA：每个查询头一组 K/V（h 组）。MQA：所有头共享一组 K/V（缓存最小）。GQA：折中——比如 32 个 Q 头共享 8 组 K/V，则 KV 缓存相对 32 组的 MHA 约缩到四分之一。注意这是按 KV 头数估算缓存张量的比例；峰值显存还包括权重、激活和工作区，效果质量也必须实测。不同版本的模型系列可能采用不同设置，查论文或模型配置比记家族名字可靠。

11.3 规模的物理学：Scaling Law

Scaling law（缩放规律）描述的是一类经验观察：在特定训练目标、数据分布和算力范围内，验证损失常随参数量 N、训练 token 数 D 增加而平滑下降，常可用幂律近似。它的价值是帮助估算边际收益、比较预算方案，而不是把「损失」直接换算成「智能」或保证能力随规模单调提升。数据污染、优化失败、架构变化、分布迁移与评测方式都会破坏简单外推；超出观察范围，拟合曲线也不再是承诺。

Kaplan 等人的 2020 年研究强调模型规模的作用；Hoffmann 等人 2022 年的 Chinchilla 工作在给定训练算力预算下重新估算参数与训练数据的计算最优分配，提出「两者都要增长」的结论。一个常被引用的粗略经验是约每个参数配 20 个训练 token，但它依赖论文中的模型族、数据、训练目标与成本假设，不能当成对所有架构/微调阶段都适用的硬门槛。常用的 dense Transformer 粗略训练算力估计为 C ≈ 6ND（浮点运算口径和实现会改变常数），它主要概括参数相关的前向与反向计算；长序列的注意力还需另计约 O(L·n²·d) 的层级交互开销。它说明增加参数、token 和上下文长度都要付算力账单。

例子有助于理解比例：Chinchilla 的计算最优实验模型约 70B 参数、训练 1.4T token；LLaMA 系列的公开论文则按不同模型规模使用约 1T 或 1.4T token。它们展示的是各自的训练预算选择，不应拼成「同一条公式推导出的所有正确答案」。给定预算时，小模型多看数据可能优于大模型少训练；但部署延迟、服务成本、数据重复度和目标质量也会改变最终选择。

因此读 scaling law 图时要先看坐标是什么：横轴可能是参数量、数据 token 或训练 FLOPs；纵轴可能是验证交叉熵，也可能是某项任务分数。拟合出来的指数与截距只对特定实验范围成立。若研究问题换成指令遵循、长上下文检索或推理时延，光看预训练 loss 曲线就不足以判断模型好坏。扩规模决策应同时估训练预算、部署成本和目标评测，并留出足够数据做真实验证。

为什么偏偏是 Transformer 吃到了规模红利

CNN、RNN 与 Transformer 采用了不同的归纳偏置与计算并行方式：卷积天然重用局部模式，循环网络按状态顺序处理，注意力允许一层直接建立远距离 token 交互。偏置既可能限制某些任务，也可能降低数据需求、提高样本效率；规模本身不会自动抹平差异。Transformer 的重要优势之一是训练时序列位置可并行计算，同时有灵活的全局信息路由，但成本是全注意力的序列长度二次项。讨论「谁更通用」时要把任务、训练预算和部署约束摆到同一张桌上。

11.4 长上下文的攻防战

长度为 n 的全量自注意力，每层注意力分数矩阵有 n×n 项，计算大致为 O(n²d)，朴素实现还会保存二次规模的中间矩阵；整层也含有投影和 FFN 的约 O(nd²) 工作。长上下文成本因此不只是「把位置编码拉长」。从数万到数十万 token 通常要组合多种算法、训练与服务优化：

  • FlashAttention（精确算法 + GPU 工程）：按块计算 Q/K/V 注意力，用在线 softmax 累积结果，减少 HBM 与片上 SRAM 之间的读写，不把完整 n×n 矩阵存下来。它仍实现标准全注意力，理论上保持同一计算结果（浮点舍入会有微小差异），并没有把二次注意力运算改成线性。
  • 稀疏/滑窗注意力（改变连接图）：Longformer 组合局部窗口与少数全局 token；滑窗模型让每个 token 只连到附近一段位置，能降低注意力工作量，但远距离信息必须靠多层传播或额外全局机制。
  • 位置扩展（改变位置输入或训练配方）：RoPE 缩放、YaRN 等可帮助已有模型适应更长位置区间，但扩展后质量并非自动维持。通常还需长上下文继续训练、数据配方和针对长距离检索/推理的评测。
  • 状态空间模型（另一种序列算子）：Mamba 一类选择性状态空间模型用随序列长度近似线性增长的扫描计算，适合研究长序列吞吐；其状态压缩、并行性、硬件效率与注意力可直接检索历史 token 的能力各有取舍，不能简单说已取代 Transformer。

「模型接受 128K token」描述的是接口或训练配置能处理多长输入；「模型会有效利用 128K 中任何位置的信息」是另一件事。长提示可能因为注意力稀释、位置偏差、检索难度或训练分布不足而出现中间信息遗失。测试长上下文要改变相关证据的位置与干扰项，测召回、组合推理和整体质量，不能只在 tokenizer 后得到一个长度数字就宣布解决。

工程上还要把提示 token 数、生成 token 数与缓存上限分开。一个请求的总上下文通常满足 prompt_tokens + generated_tokens ≤ context_window，但具体服务可能预留系统模板、工具调用或安全标记的预算。KV cache 不仅由序列长度决定，也依赖并发数和 KV 头布局；即使模型权重能加载，服务也可能因缓存预算不足而拒绝大 batch。长上下文能力因而同时是位置泛化、训练数据、算法算力与在线内存管理问题。

11.5 常见问题 FAQ：从模型家族读到工程选择

Q1：BERT 和 GPT 都能接分类头，分类任务该选哪一个？

若任务的输入句子在预测前已经完整可见，encoder-only 表示通常很自然：每个位置可融合左右上下文，再从专门位置（例如池化后的表示）接分类头。Decoder-only 也可以对完整输入做分类：把标签写成续写 token，或在最后一个输入位置接分类头；但它的位置表示遵守因果顺序，较早位置看不到后文。是否更好要看训练数据、微调目标、上下文长度、吞吐和部署接口，不是只由“能不能分类”决定。

检索也要区分“得到向量”和“得到好向量”：取 BERT 的 [CLS] 或平均池化不会自动保证语义相似度排序良好；通常需要匹配检索目标的对比学习或监督微调，并按目标语料评估召回率。GPT 的隐藏状态同样可用于表征，但也需要合适的池化、微调与评测。选架构前先列出输入是否完整可见、输出要类别还是向量、训练标签从哪里来。

Q2：BERT 预训练里的 [MASK] 为什么不是普通推理时必须提供的标记？

[MASK] 是原版 BERT 构造填空训练样本时使用的专用 token，不是每个下游输入都必须插入的提示符。分类、句对判断或抽取式问答通常直接输入真实文本与相应结构标记；模型输出的是任务头所定义的标签或位置。若要做填空，就在目标位置放入模型认识的 mask token，再读取该位置的词表分布。

一次填一个洞的预测分布以左右上下文为条件；有多个洞时，逐个填入并重新预测是一种启发式迭代，并不自动等同于一个按左到右分解、经过联合最大似然训练的生成过程。训练中确有一部分被选中的位置保留原词或换成随机词，以减轻模型把 [MASK] 当成唯一线索的倾向；但目标仍是被选位置的条件填空。理解这个接口差别，能避免把 MLM 的每个词表 logits 误当成 GPT 式的下一个 token 分布。

Q3：GQA 把多个注意力头合成一个头了吗？

没有。GQA 保留多组 Query 头，只让若干 Query 头共享一组 Key/Value 头。比如 h_q=32、h_kv=8、d_head=128 时，Q 仍为 (B,32,T,128)，K、V 各为 (B,8,T,128)；每四个 Query 头按配置映射到一组 K/V，最终仍产生 32 个 query-head 的上下文输出，再拼接并投影回模型宽度。

相对 32 组 K/V 的 MHA，这个例子的 K/V 缓存元素数约为四分之一，K/V 投影也更小；Q 投影、Query 头数量和注意力输出并没有按四分之一缩减。要正确运行，注意力实现必须支持这种头映射，不能把 K/V 张量硬 reshape 成 32 个独立头。质量影响取决于训练和具体任务，需要用同等数据、训练预算和评测来验证。

Q4：FlashAttention 和 GQA 都能帮长上下文提速，它们能互相替代吗？

它们优化的是不同账目。FlashAttention 按块执行精确的密集注意力并在线累计 Softmax 结果，避免把完整 T×T 分数/权重矩阵写入高带宽显存，从而减少中间存储与显存读写；密集注意力连接和二次级算术仍在。它主要改变注意力 kernel 的执行与内存访问方式，不会把生成时逐层保存的 K/V 头数自动减小。

GQA 则让多组 Query 共享较少的 K/V 头，直接压低 K/V 投影和每个 token 的缓存体积，但需要合适的训练配置与内核支持。两者通常可以组合：一个减少注意力中间张量的显存流量，另一个减少长期 KV 状态。是否真的更快要在目标 GPU、序列长度、并发、精度和库版本上测量；小序列或低并发场景可能由别的开销主导。

12.1 多头自注意力（含因果掩码）

attention.pyimport torch
import torch.nn as nn

class CausalSelfAttention(nn.Module):
    def __init__(self, d_model, n_head, max_len):
        super().__init__()
        assert d_model % n_head == 0
        self.n_head = n_head
        self.d_k = d_model // n_head
        self.qkv = nn.Linear(d_model, 3 * d_model, bias=False)  # 三个投影合一，省 kernel 调用
        self.proj = nn.Linear(d_model, d_model)                   # W^O：多头合议
        mask = torch.tril(torch.ones(max_len, max_len, dtype=torch.bool)) # True 表示允许读取；下三角包含自身
        self.register_buffer("mask", mask.view(1, 1, max_len, max_len))

    def forward(self, x):                       # x: (B, T, C)
        B, T, C = x.shape
        q, k, v = self.qkv(x).split(C, dim=2)   # 三个 (B,T,C)
        q = q.view(B, T, self.n_head, self.d_k).transpose(1, 2)  # (B,h,T,d_k)
        k = k.view(B, T, self.n_head, self.d_k).transpose(1, 2)
        v = v.view(B, T, self.n_head, self.d_k).transpose(1, 2)

        score = (q @ k.transpose(-2, -1)) / self.d_k ** 0.5      # 式4-2 的 QKᵀ/√d_k
        score = score.masked_fill(~self.mask[:, :, :T, :T], float("-inf"))
        attn = torch.softmax(score, dim=-1)                       # 行和=1 的权重
        out = attn @ v                                            # (B,h,T,d_k)
        out = out.transpose(1, 2).contiguous().view(B, T, C)      # 拼回头部
        return self.proj(out)

让 B=2、T=5、C=256、h=4。输入 x 是 (2,5,256)；合并线性层产生 (2,5,768)，沿最后一维切成三个 (2,5,256) 的 Q/K/V；每个向量被拆成 4 个 64 维头后，变为 (2,4,5,64)。于是 q @ kᵀ 得到 (2,4,5,5)，每个 batch、每个头、每个查询位置，都有一行针对 5 个 key 的分数。把未来位置置为 −∞ 后做 softmax，仍沿最后一维归一；注意力乘 V 得到 (2,4,5,64)，拼回头后成 (2,5,256)，再过输出投影。

qkv 是三个线性投影的融合实现：最后一维连续包含 Q/K/V 三段，数学上可等价于分别调用三个 Linear（权重和 bias 要一一对应）。融合通常可减少 kernel launch 与调度开销，实际加速依硬件和实现而异。register_buffer 让固定掩码随模型移动设备、进入 state_dict（本例默认持久化）但不参与梯度；掩码元素数是 max_len²，布尔 dtype 比 FP32 更省空间。真实大模型常用按需因果 kernel 避免为每个长度保存完整三角矩阵。这个最小代码没有 padding mask，所以一个 batch 内应该使用等长、不含 PAD 的定长块；若使用变长序列，需要在因果限制之外屏蔽 padding key，并在 loss 中排除 padding label。整行被屏蔽会让 softmax 产生 NaN，因此实现必须确保每个有效 query 至少有可见 key。

把注意力形状拆成轴来读：(B,h,T,dₖ) 中的 B 是互不混淆的样本，h 是并行子空间，T 是 query/key 位置，dₖ 是每头通道数。转置后的 key 形状为 (B,h,dₖ,T)，最后两维相乘才得到 (B,h,T,T)。因此 softmax(dim=-1) 沿着「一个 query 可以选哪些 key」归一，每个有效 query 行和为 1。随后 attn @ v 对 key 位置加权求和，消掉 key 轴并保留 value 通道，得到 (B,h,T,dₖ)。若 softmax 写成 dim=-2，归一对象就变成 query 行，数学含义错了；形状往往依然合法，所以这类 bug 不能只靠程序不报错发现。

在此例中，每层注意力的两次主矩阵乘法约各需要 B·h·T²·dₖ 次乘加；把乘加按 2 FLOPs 计，合起来约 4B·T²·C FLOPs，另有 QKV/输出投影、Softmax 和逐位置 FFN。score 与权重两个中间张量各有 B·h·T² 个元素。小 T 时投影/FFN 可能比注意力矩阵更显著；很长 T 时二次项会迅速成为显存或计算瓶颈。FlashAttention/SDPA 通过分块和融合降低中间矩阵的读写或存储需求，仍计算相同的全注意力连接，不会消掉标准全注意力的二次算术规模。

PyTorch mask 语义提醒

本例自己把 True 定义为「允许读取」，所以用 ~mask 找到未来格并填 −∞。PyTorch 不同 API 的布尔 mask 约定并不统一；例如 scaled_dot_product_attention 的 bool mask 中 True 表示参与注意力，而 MultiheadAttention 的某些 padding mask 中 True 表示屏蔽。迁移代码时先查当前 API 文档或显式造一个 2×2 小例子验证，不能仅凭变量名 mask 判断语义。

因果矩阵，拿纸验证

长度 T=4 时，位置 0 的 query 只读 key 0；位置 1 读 key 0–1；位置 2 读 key 0–2；位置 3 读 key 0–3。掩码广播到 (B,h,T,T)，行对应「谁在提问」，列对应「可读的 key」。如果把矩阵上下翻转，模型会向未来泄漏目标答案。

注意力的理论计算量包含 QK 分数与加权 V 两次序列交互，随 T² 增长；朴素写法还显式生成 score 与 attention 两个 (B,h,T,T) 中间张量。生产版可用 PyTorch 的 scaled dot product attention/FlashAttention，让 kernel 融合缩放、mask、softmax 和加权，但概念和 shape 不变。

12.2 Transformer 块与整机

块里的 Pre-LN 顺序是：输入流 x 先归一化，再供注意力读取，注意力结果加回残差；新流再做一次归一化、逐位置 FFN、第二条残差。FFN 对每个 token 独立使用同一套权重，所以它不会让位置彼此交流；跨位置的信息交换发生在 attention。nn.Sequential 保持层的顺序，但生成任务最终仍需因果注意力。

model.pyclass Block(nn.Module):
    # Pre-LN 结构：x + attn(LN(x)) → x + ffn(LN(x))（对应 7.2/7.3 节）
    def __init__(self, d_model, n_head, max_len):
        super().__init__()
        self.ln1 = nn.LayerNorm(d_model)
        self.attn = CausalSelfAttention(d_model, n_head, max_len)
        self.ln2 = nn.LayerNorm(d_model)
        self.ffn = nn.Sequential(
            nn.Linear(d_model, 4 * d_model),   # 式7-3：先升 4 倍
            nn.GELU(),                            # 现代替代 ReLU 的平滑版
            nn.Linear(4 * d_model, d_model),    # 再降回
        )
    def forward(self, x):
        x = x + self.attn(self.ln1(x))   # 残差：修订模式，原稿永存
        x = x + self.ffn(self.ln2(x))
        return x

class MiniGPT(nn.Module):
    def __init__(self, vocab, d_model=256, n_head=4, n_layer=4, max_len=128):
        super().__init__()
        self.tok_emb = nn.Embedding(vocab, d_model)      # 第2章：词向量查表
        self.pos_emb = nn.Embedding(max_len, d_model)    # 可学习位置编码（7.1）
        self.blocks = nn.Sequential(*[Block(d_model, n_head, max_len) for _ in range(n_layer)])
        self.ln_f = nn.LayerNorm(d_model)
        self.head = nn.Linear(d_model, vocab, bias=False) # 落到词表

    def forward(self, idx):                       # idx: (B,T) 的 token 编号
        B, T = idx.shape
        x = self.tok_emb(idx) + self.pos_emb(torch.arange(T, device=idx.device))
        x = self.ln_f(self.blocks(x))
        return self.head(x)                       # (B,T,vocab) logits

输入 token id idx: (B,T) 通过 embedding 查表为 (B,T,d)。torch.arange(T) 生成位置 (T,)，查位置表得到 (T,d)，利用广播加到 batch 中每条序列上。每个 block 仍输出 (B,T,d)，最终线性头把每个位置投影成词表分数 (B,T,V)。这段代码使用学习型绝对位置嵌入，所以 T 不能超过 max_len；位置向量不会因模型深度而自动变成 RoPE。

逐行检查整机的轴语义：embedding 的索引表有 V 行、每行 d 个可训练数；输入 idx 应是整数 ID，且所有值都落在 [0,V)。位置索引是 0…T−1，同一批样本共享同一套位置向量，所以 (T,d) 广播成 (B,T,d)。每个 block 保持最后一维 d 不变，才能与残差 x 逐元素相加。最后的词表头把每个位置上的 d 维隐藏状态映射为 V 个 logits；softmax 通常留到抽样或计算概率时再做，训练交叉熵函数直接接 logits 更稳定。

这个例子每层内部 FFN 宽度设为 4d。第一层线性映射把 (B,T,d) 扩至 (B,T,4d)，GELU 在最后一维逐元素加入非线性，第二层再映回 (B,T,d)。每个 token 使用同一组 FFN 权重，但不同位置各自运算；如果只有 FFN 而没有 attention，位置间信息不会交换。反过来，attention 为各位置路由上下文，FFN 再对更新后的每个位置做通道混合。把二者职责分开，会更容易理解为什么一个 Transformer block 同时需要它们。

head 这里有自己的输出权重，参数量约为 V×d；如果希望与输入 token embedding 权重共享，可显式令 self.head.weight = self.tok_emb.weight，前提是两者形状兼容。共享会减少参数，但不是本例代码当前做的事。nn.LayerNorm(d) 默认有可学习的缩放与偏移参数；小模型若使用 fp16，某些算子和 softmax 数值稳定性要谨慎，教学实现建议先跑 FP32 或 BF16，再做性能优化。

按默认值 V=5000,d=256,n_layer=4,max_len=128 粗算，token embedding 与独立输出头各有 5000×256=1,280,000 个权重；位置表约 128×256=32,768 个数；每层大约 0.79M 参数（包括 QKV、输出投影、LayerNorm 与 4d FFN），四层约 3.16M。整机合计约 5.75M 参数，具体数会受 bias、权重共享等设置影响。这个量级帮助你看出词表头并非「免费」：词表翻倍会增加 embedding 与输出投影的参数，还会让每个位置的 logits 变宽。

可学习绝对位置表还带来清楚的能力边界：最多直接索引 max_len 个位置；推理时若输入长度更长，embedding 索引就越界。即使把表插值或扩展，也不代表模型已经学会在新长度上可靠工作。另一方面，若缓存式推理只输入新 token，位置编号必须继续递增，而不能每轮都重新从 0 编号；本章的 forward(idx) 会对所传完整前缀从 0 生成位置，因此它是无 KV cache 的教学前向，并没有实现高效增量生成。

12.3 训练循环：九行里的全部学问

train.pyimport torch.nn.functional as F

model = MiniGPT(vocab=5000)
opt = torch.optim.AdamW(model.parameters(), lr=3e-4, weight_decay=0.1)

for x, y in loader:                        # x=tokens[:, :-1], y=tokens[:, 1:]
    logits = model(x)                        # (B,T,vocab)
    loss = F.cross_entropy(
        logits.reshape(-1, logits.size(-1)), # (B·T, vocab)，每行是一份词表分布
        y.reshape(-1),                       # (B·T)，每项是目标 token ID
        ignore_index=-1)                    # 只有 loader 确实用 -1 填 PAD 才这样设
    opt.zero_grad(set_to_none=True)
    loss.backward()                          # 梯度逆流两座塔（9.4）
    torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)  # 防爆
    opt.step()

x 和 y 的序列长度相同，但错开一个 token：输入是 [BOS, A, B] 时标签为 [A, B, EOS]。第一个 logits 学会预测 A，第二个预测 B；因果 mask 允许它们在同一个 batch 前向时并行计算。cross_entropy 的类别轴必须是最后那个 vocab 轴；这里先把 (B,T,V) 摊平为 (B·T,V)，标签同步摊为 (B·T)，才能让每一行 logits 与一个类别 ID 一一对应。默认 reduction 是所有非忽略项的 mean；若改成 sum，就要相应调整学习率或累积批次的缩放。若一个 batch 全是 ignore label，mean 的分母为零，训练数据应保证每个更新批次至少有一个有效目标。

如果数据中有多个独立文档拼接，要在边界放 EOS 或使用明确的边界策略，避免模型把无关文档前后文当成自然连续文本。忽略标签不会自动屏蔽 attention 中的 PAD key：loss mask 决定哪些答案参与梯度，attention mask 决定 query 可以读取哪些输入位置，二者职责不同。常见 bug 是把 PAD 标签设为 ignore，却忘记屏蔽 PAD key，导致真实 token 的注意力分布仍会把概率分给补位位置。

梯度裁剪把全模型梯度范数限制在设定值，通常在反向之后、优化器更新之前操作；若使用混合精度梯度缩放，应先 unscale gradients 再裁剪。更完整的训练脚本还要调用 model.train()，验证时改用 model.eval() 和 torch.no_grad()；保存 optimizer state 与随机数状态才能真正续训。生产训练还需学习率调度、checkpoint、数据断点、日志与溢出检测。

  2. masked_fill 为什么填 -inf 而不是一个很大的负数如 -1e9？
  3. Pre-LN 版 Block 中，梯度沿哪条路径无衰减地流过 100 层？
查看答案

① 数学完全等价（拼接的输出维度），工程上合并投影可减少 kernel 调度次数，实际收益看实现。② -1e9 超出 FP16 可表示范围，转换时可能溢出或报错，跨 dtype 不稳妥；填 -inf 可让被屏蔽位置 softmax 概率严格为零，但每个有效 query 必须至少留一个可见 key，否则整行全是 -inf 会产生 NaN。实际项目也可使用经过核对的 fused SDPA 因果 mask。③ 恒等路径：x 本身——每层只加增量，反向中 ∂(x+F)/∂x 含直接的 1 项，使梯度有一条不经过 F 的路径；完整梯度还包含 F 对 x 的导数，不能说总梯度严格等于 1。

12.5 常见问题 FAQ：沿着张量 shape 找代码问题

Q1：为什么要把 (B,T,V) 展平？怎么保证 logits 和标签还对得上？

交叉熵需要把每个待预测位置视为一条独立分类样本：V 个类别分数对应一个目标 token ID。将 logits 从 (B,T,V) 变成 (B·T,V)，同时把标签从 (B,T) 变成 (B·T,)，就把 batch 与位置两轴并入样本轴，保留最后的词表类别轴。若二者都按相同的 batch-major 顺序摊平，第 b·T+t 行 logits 就仍对应第 b 条序列第 t 个目标。

错位通常来自只切了输入或只切了标签、在其中一边改变了轴顺序、或对 logits 用错类别维。调试时可取 B=2,T=3，把每个位置的预测写成不同标记，并打印同步摊平的标签索引；再确认输出末维正好是 V、标签是整数类别 ID 且范围在 [0,V)。PAD 目标另行忽略，不能靠展平本身解决。

Q2：为什么 transpose 后直接 view 有时会报错，或得到意料外的布局？

张量除了形状，还有 stride（每个轴移动一个单位时，底层存储跨过多少元素）。transpose/permute 通常只交换 shape 与 stride，不会搬动数据；结果可能不再连续。view 要求新形状能由现有 stride 直接解释，因此非连续张量常会报错。不要把它误认为注意力数学公式错了，也不要仅为了让报错消失而随意改轴顺序。

若确实要改变布局，可显式调用 x.contiguous().view(...)，接受可能发生的数据复制；或用 reshape(...)，它在可行时返回视图、不行时自动复制。无论哪种方式，都应先按轴语义确认要合并的是哪些维度。例如多头输出常先从 (B,h,T,d_head) 转成 (B,T,h,d_head)，再合并最后两维为 (B,T,C)；把转置方向写反可能仍然可执行，却把不同 token 的通道混在一起。

Q3：推理时调用 model.eval() 就等于关闭梯度、节省推理显存了吗？

不是。eval() 把模块切换到评估模式，主要让 Dropout 停止随机丢弃，并让 BatchNorm 使用评估统计；它不会关闭 autograd，也不会阻止梯度图建立。torch.no_grad() 或更有针对性的 torch.inference_mode() 才会停止记录推理所需梯度，从而减少内存与反向开销。它们彼此独立：训练模式下可以暂时禁用梯度做分析，评估模式下也可以开梯度做某些优化。

普通推理通常同时使用 model.eval() 和 torch.inference_mode()。注意 LayerNorm 不像 BatchNorm 那样依赖跨 batch 的运行统计，切换 eval() 不会改变它的数学行为；若一个模型完全没有 Dropout 等模式相关模块，输出可能看不出变化，但设置评估模式仍是稳妥约定。排查训练与验证结果不一致时，要把模式切换和是否建梯度分别检查。

Q4：shape 全都对，怎样验证 causal mask 没把未来信息漏进去？

给定长度 T 的因果注意力，score 轴应表示 query 位置乘 key 位置，即每个 batch、每个头的分数为 (T,T)；行是提问的 query，列是可读取的 key。沿 key 轴做 Softmax 后，每个有效 query 行的权重和应约为 1，未来列的权重应为 0（数值容差下检查）。但只看 shape 或总和不足以证明方向正确：错误的上/下三角仍可能形状合法、行和也为 1。

可以做一个因果性单元检查：保持位置 0…i 不变，只改位置 i+1…T−1 的 token，再比较位置 i 及其之前的 logits；正确的因果模型不应受后缀影响。还可用极小长度打印 mask 和 attention weights，确认有效位置各自只对前缀归一。测试时需关闭 Dropout、固定模型状态，并确保没有跨位置的双向归一化等其他路径，否则噪声会掩盖问题。

13.2 高频误区排行榜

误区 ①

"注意力权重高 = 那个词重要"。错——它是信息路由的份额，不是因果解释。可解释性需要专门方法（探针、消融、机制可解释性）。

误区 ②

"注意力自己天然知道词序"。错——标准 self-attention 对输入排列是等变的；模型通常通过位置表示与因果可见范围获得顺序线索。具体位置机制并不总是一个可相加的绝对位置向量。

误区 ③

"Q、K、V 是三个不同的词"。错——是同一词向量经三个不同矩阵投影出的三种角色。

误区 ④

"掩码是为了防过拟合"。错——因果掩码是为了防信息泄漏（抄袭未来答案），与 dropout 的动机完全不同。

误区 ⑤

"大模型只是在背更多文本"。规模和数据有时伴随新能力或基准上的明显跃升，但「涌现」是否突然出现，会受评测指标、提示方式和任务阈值影响；不能把它当成所有模型都会按规模自动获得推理能力的保证。

误区 ⑥

"训练和推理是一回事，只是训练多算几个 token"。训练常用真值前缀与 teacher forcing，一次并行得到许多位置的损失；生成阶段没有未来真值，必须逐步把已选 token 接回去。因果掩码使两者的信息可见范围相容，但训练前缀和推理前缀的来源不同。

误区 ⑦

"KV cache 把注意力变成常数时间"。它避免重复算旧 token 的 K/V 和历史层状态，但新 Query 仍需读取此前 K/V；单步读取量随上下文长度增长，缓存显存也随 token 数增长。

误区 ⑧

"损失下降就表示事实可靠"。交叉熵衡量目标 token 在指定数据分布下的概率，不是事实核查器；训练语料偏差、数据污染和分布迁移都可能让低 PPL 与正确回答脱钩。

误区 ⑨

"注意力、FFN、位置编码是同一类模块"。注意力在位置之间路由信息，FFN 对各位置分别做通道非线性变换，位置机制提供次序信号；shape 看起来接近，不代表功能相同。

误区 ⑩

"参数量相同，模型成本就相同"。序列长度、注意力实现、KV 头数、并发 batch、精度与硬件都会改变训练或服务成本；比较架构要分别报告参数、训练 token、上下文与时延/吞吐条件。

诊断口诀

先问目标函数，再画可见范围；先写每个张量的轴，再检查 mask 与标签是否同一语义；推理时分清「模型分布」和「采样策略」；谈成本时分开参数、算力和缓存。很多 Transformer 疑问都能沿着这四个问题定位。

13.4 结课演练：从一句提示追到下一个 token

最后用一条玩具提示把所有零件接起来。设一个 decoder-only 模型收到 小猫 追着 球 它，现在要预测下一个 token。以下分数和向量只是教学用的小数字，不是任何真实模型的参数，也不表示注意力能读出人类定义的“正确答案”。

① 文本先变成 token ID，再查嵌入表

假设 tokenizer 把提示切成 4 个 token，ID 是 [17, 203, 58, 91]。这些编号只是词表地址。嵌入表查出四行后，位置机制再提供顺序线索，得到 X ∈ R^(1×4×d_model)：1 是 batch 大小，4 是上下文 token 数，d_model 是每个 token 的隐藏宽度。

② 一层里先做因果自注意力

所有位置投影出 Q/K/V。每个查询与可访问的键做点积并除以 √d_k；位置 1 只能看位置 1，位置 2 能看 1–2，位置 4 能看 1–4。Softmax 权重乘 Value 后，位置 4 获得一份来自整个前缀的加权混合。玩具地给位置 4 的注意力权重设为 [0.36, 0.14, 0.17, 0.33]，它们相加为 1；真实权重由模型参数和输入实际计算，不能手工指定。

③ 残差流继续通过 FFN 和多层堆叠

注意力输出过输出投影并进入残差分支；归一化后，逐位置 FFN 做非线性变换，输出再回到 d_model 宽度。重复这些块后，取最后一个 token 的隐藏状态 h₄。它已沿层级混合当前前缀的信息，但仍是一个向量，不是已经完成的自然语言句子。

④ 词表投影生成 logits，解码策略选 token

语言模型头计算 z = h₄W_vocab + b，得到词表大小 |V| 的分数。Softmax 可把它变成下一个 token 的条件分布。贪心取最大概率项可能得到 累；温度采样或 Top-p 则会按修改后的候选分布抽样。这个选择是“在当前模型分布下怎么解码”，不是对事实真假的保证。

⑤ 选出的 token 接回前缀，再继续

若选出 累，下一轮上下文就成为 小猫 追着 球 它 累。KV Cache 保留前面各层已算出的 Key/Value，新 token 只需计算自己的投影并读取缓存。若生成 [EOS]、命中停止规则或到达上限，循环结束。训练时则用正确后缀做监督，因果掩码确保每个位置只用可见前缀。

把它画成一张图

字串 → token ID → 嵌入 + 位置 → (Q,K,V) → 因果注意力 → 残差与 FFN → 隐藏状态 → 词表 logits → 解码选词 → 回到字串。训练时，数据集给出下一 token 的真值，损失沿这条图反向传播；推理时，模型自己选出的 token 进入下一轮。整份讲义讲的公式、结构和工程优化，都是在回答这条流水线里的某一个问题。

◈ 最终自测：不看前文，自己画出完整数据流

  1. 输入 4 个 token、隐藏宽度 512、8 个注意力头时，单头宽度是多少？每层注意力分数矩阵每个头是什么形状？
  2. 生成位置 4 的 token 时，因果掩码允许它看哪些输入位置？训练算位置 4 的损失时，输入前缀与推理时的内容一定相同吗？
  3. 如果温度变高，所有候选 token 的相对排序会变吗？概率分布有什么变化？
  4. KV Cache 保存什么、节约什么，又要付出什么代价？
  5. 一层注意力输出后为什么不能直接把宽度从 512 改成任意数字？残差加法要求什么？
查看推理过程与答案

① 单头宽度 512÷8=64；对长度 4 的序列，每头的分数矩阵为 (4×64)(64×4)=4×4（批次和 head 维度时整体为 (B,8,4,4)）。② 位置 4 可以看到 1–4；训练标签对应“第 4 个输入位置之后的目标 token”。训练位置可见的前缀范围和推理一致，但训练前缀通常来自真值，推理前缀来自模型已生成内容，不保证 token 内容相同。③ 正温度缩放不改变 logits 的排序；温度高时分布趋平，低概率 token 更可能被抽中。④ 缓存每层过去 token 的 Key/Value，减少逐步生成时对旧 token 的重复投影计算；代价是与 batch、层数、上下文长度、KV 头数和数据精度相关的显存占用。⑤ 残差两支必须同形状或可广播兼容；标准 Transformer 会把注意力输出投影回残差流宽度，使其可与原输入相加。

如果五题都能解释“为什么”，而不只报数字，说明你已经能把注意力公式、掩码、训练输入、推理解码和 KV Cache 放回同一条因果链里。下一步读代码时，先写每个张量的 shape，再读运算符；这比背类名更不容易迷路。

13.5 常见问题 FAQ：把复习变成可复现的判断

Q1：开始复现一个小型 Transformer 前，必须先学完微积分和概率论吗？

不必等到修完所有高等数学课程才动手，但需要逐步补齐几个直接用得到的工具：向量与矩阵乘法、转置和维度；概率分布与 Softmax；负对数似然/交叉熵；链式法则和“梯度指向怎样改变损失”的直觉。先能计算点积注意力、确认概率和为 1、说明一项交叉熵的由来，就足以读懂一个小模型前向与基本训练循环。

建议把数学与代码并行推进：遇到 QKᵀ 就检查两侧维度，遇到 Softmax 就说明沿哪个类别/Key 轴归一，遇到反向传播就先理解局部梯度如何沿链式法则相乘。矩阵微分、优化器收敛理论和概率图模型会帮助你深入研究，但不是第一次运行迷你 GPT 的门槛。若代码报错或结果异常，应回到可手算的短序列与显式 shape，而不是先去背更多名词。

Q2：验证 loss 很低，为什么模型在新问题上仍可能答错？

验证 loss 衡量模型在指定留出文本上的 token 预测概率，前提是验证数据与训练数据真正隔离、评估口径正确。它不直接测事实核查、工具调用、长距离检索或用户是否满意。若训练集与验证集有近重复、评测语料泄漏、数据分布和实际问题不同，数字会给人过于乐观的印象；即便隔离完善，语言分布拟合更好也不保证每类任务同步提升。

因此把预训练指标和目标任务评测分开报告：检查文档级去重和时间切分，报告 tokenizer、有效 token 计数、上下文窗口与 PPL 口径；再用独立任务集测准确率、召回、校准、生成质量或安全边界，并审查错误案例。PPL 适合诊断语言建模的概率拟合，不应代替系统真正要完成的工作指标。

Q3：怎样公平比较两个架构或优化改动？

先明确比较的问题，再控制其他变量。若要判断 GQA 是否减少缓存成本，应尽量固定权重规模、训练数据、训练 token、精度、硬件、并发和上下文长度；若更换 tokenizer，就要重新核算输入 token 数与输出词表成本；若改变预训练目标，就不能只把同一 benchmark 分数当作唯一证据。报告参数量、训练计算预算、数据与去重规则、上下文长度、解码参数和评估集，读者才知道结论的适用范围。

系统优化要同时报告质量与成本：在一致的目标质量下比较吞吐、首 token 延迟、每 token 延迟、峰值显存和可承载并发；不同优化可能只改善训练内存、只改善 KV 容量，或只在长序列更有效。做小型消融、重复关键测量，并在目标设备验证，比单看架构名、参数量或一次漂亮的生成样本更可靠。

Q4：模型输出异常时，按什么顺序定位问题最快？

先固定模型版本、输入 token IDs 和解码设置，把“模型算了什么”与“采样怎么选”拆开：确认聊天模板和特殊 token 没有意外改变，查看最后位置 logits 的有限性、概率归一和高分候选；用贪心或固定随机种子建立可复现基线，再逐个恢复温度、Top-p、重复惩罚和停止条件。若只是温度或候选截断变化导致输出差异，问题在解码策略；若 logits 本身异常，再向前检查输入长度、位置编号、mask、权重与数值精度。

对带缓存生成，还要把相同前缀分别用“全量重算”和“增量 KV cache”跑一两步，对照 logits；不一致时优先检查 cache 是否对应同一 token 前缀、各层位置偏移是否正确、追加 K/V 的序列轴是否正确。先缩到一个 batch、少数 token、单步前向，往往比直接看一整段生成更容易定位。每次只改一个因素，并保存复现输入与配置，才能确认修复没有把问题转移到别处。

14.3 训练阶段 A：准备右移目标和 teacher forcing

翻译数据集给模型的监督样本是一对句子 (x,y)。编码器读源句 x；训练时解码器输入由标准译文右移一位构成，标签则是要预测的下一 token：

本例的目标输入长度是 5，标签也为 5。训练不需要模型先猜对 I 才能训练 love：位置 2 的输入直接使用标准答案中的 I，所以一次前向便能并行算 5 个位置的预测。模型仍看不到其所在行之后的标签——因果掩码会在 attention logits 上把未来位置加成 −∞，Softmax 后未来权重为 0。

训练与推理仍有一处重要不一致

可见的位置范围一致：位置 i 只能读取前缀。但训练前缀来自译文真值，推理前缀来自模型先前的输出。若推理时较早位置生成了错误 token，后续条件分布也会改变。这就是暴露偏差的一个来源；掩码保证因果性，却不会保证模型每轮生成都正确。

14.4 训练阶段 B：嵌入、位置线索、编码器 H

为了看清形状，我们采用原论文 Base 配置作为尺寸参照：d_model=512、h=8，每头宽 d_k=d_v=64，前馈宽 d_ff=2048，编码器与解码器各堆叠 6 层。它只是一个历史配置参照；许多现代模型的层数、宽度、词表和位置机制都不同。

  1. 查源端嵌入。4 个 source ID 查出矩阵 E_s ∈ R^(1×4×512)；“1”是 batch size。
  2. 注入顺序线索。原论文将正弦 PE 加到 embedding 上，形状仍是 (1,4,512)。这使位置 1 的“猫”与位置 3 的“猫”有不同位置表示。
  3. 每层编码源句。每头 Q/K/V 为 (1,8,4,64)，打分矩阵为 (1,8,4,4)；编码器的每个有效源位置通常能看完整源句（padding 需遮）。

  5. 六层之后得到 H。源端最终记忆 H ∈ R^(1×4×512)。这里仍有 4 行——模型没有把整句挤进一个固定长度瓶颈向量。

编码器自注意力的一行是“某个源 token 作为 Query，对各源位置的 Key 做分数”；Softmax 得到权重后，才按这些权重混合 Values。以单一头的玩具行为作讲解，如果 Query 对“猫”那一行算出 [0.05, 0.15, 0.75, 0.05]，读者可以说该头把 75% 的加权质量放到第三个源位置。这个例子是预设概率用来读图，并非我们已经训练出能懂猫的模型。

14.5 训练阶段 C：解码器如何同时问过去与源句

目标侧也查 embedding 并加位置线索，训练输入形状是 (1,5,512)。解码器一层有三种子层工作，顺序分别是掩码自注意力、交叉注意力和 FFN：

交叉注意力是 Seq2Seq 的接线桥。“cats”预测位置的 Query 来自英文目标侧；编码器的 4 个源向量投影成 K/V。所以该位置生成 cats 时可以同时查询源句中的“我”“爱”“猫”“。”。假设一个玩具 cross-attention 头的权重是 [0.03,0.10,0.82,0.05]，它显示该位置在这一头上主要读取“猫”。真实权重由训练过的投影与当前隐藏状态决定；单独看权重也不能据此断言模型真正“理解”了指代。

上述 cross-attention score shape 的推导是：目标 Q 是 (B,h,T,d_k)=(1,8,5,64)；源 K 转置后是 (1,8,64,S=4)；乘起来就是 (1,8,5,4)。最后一个 4 不是目标长，而是源句的位置数。乘 Value 后得到 (1,8,5,64)，拼 8 个头并过输出投影，再回到目标残差流 (1,5,512)。

别把三张“概率表”混成一张

① self-attention 的 Softmax：目标位置对目标前缀内部做信息混合；② cross-attention 的 Softmax：目标位置对源句做信息混合；③ lm head 的 Softmax：对整个目标词表里的 token 类别归一化。前三者虽都用了 Softmax，但归一化轴不同、问题也不同。前两类给的是跨位置的路由权重，第三类才是下一 token 的分类分布。

选中真值类别的负对数概率

每个位置只对正确标签对应的 Softmax 概率取 −log p。正确概率越小，该位置惩罚越大；多个 token 的损失再按实现约定平均或求和。

反向传播计算梯度

链式法则从词表投影一路反向经过 decoder FFN、自注意力、cross-attention，再通过 cross-attention 的 K/V 投影回 encoder 层。源句表示若改变能降低译文损失，编码器相关参数就会收到梯度。

优化器更新所有相关权重

梯度进入 Adam/AdamW 等优化器的状态与更新规则，embedding、注意力投影、FFN、归一化等参数向降低期望训练损失的方向微调；padding 标签应排除在 loss 之外。

换下一批平行句对重复

单个例句不能教出翻译系统。模型要在大量多样的源句—译文对上重复前向、计算损失、反向和更新，才能学到可迁移的统计模式；验证集用于监控泛化，不用于反向更新。

“模型学会了这句翻译”不等于“这次 batch loss 为零”

一次更新一般只挪动参数很小的一步，会同时影响很多句子；反向传播也不会给模型存下一条“中文‘爱’永远对应 love”的词典规则。它调整共享参数，使未来不同上下文下的整体损失降低。词对齐只是众多可学习关联中的一种。

14.10 常见问题 FAQ

为什么翻译训练可以一次算 5 个位置，实际生成却一定要一词一词来？

训练时标准译文已经存在，因此把它右移后作为 decoder 输入；因果掩码保证第 i 行看不到未来标签，但矩阵运算可以并行计算所有行。推理时译文未知，第 i+1 个输入必须等第 i 步先选出 token 才能确定，所以自回归解码串行进行。训练的并行来自已知真值前缀，不代表模型提前知道未来答案。

为什么交叉注意力分数矩阵是 5×4，不能写成 4×5？

矩阵行来自 Q，列来自 K。这里 Q 来自 5 个目标侧位置，K/V 来自 4 个源侧位置，因而是 5 个目标 Query 分别对 4 个源 Key 打分，得到 5×4。Softmax 沿每行的源位置归一化，再乘源侧 V；若交换方向，含义和输出 shape 都会变。

示例里的 ID、注意力权重和 token 预测，是模型真的会产生的吗？

这些值是为了让你能手算而设定的教学数据，不来自训练或在线推理。ID 取决于 tokenizer；注意力权重由具体 Q/K 与掩码计算；生成 token 由实际 logits、温度、采样器等决定。真实运行要加载已训练模型并输入这条样本，逐步记录 tensors 才能得到观测值。讲义的目的是严格呈现每步如何连接，不把示意值伪装成测量结果。

token ID 怎么变成一句译文？模型输出 token 后还做了什么？

模型每步输出的是目标词表上的 token ID（或其分布），生成到 EOS 后，tokenizer 用自己保存的词表与合并规则把 ID 序列转换回文本。空格、标点和子词拼接规则也由具体 tokenizer 决定，所以模型生成 ID 序列与人读到最终字符串是两个相邻但不同的阶段。
